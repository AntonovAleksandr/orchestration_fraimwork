# Карточки ЛК ВБ с баркодами, которых нет в PIM

Выгрузка для контент-менеджеров: какие карточки и размеры надо поправить в
личном кабинете Wildberries, чтобы заказы по ним уезжали на склад.

| Файл | Что это |
|---|---|
| `wb-cards-with-unmappable-barcodes-2026-07-27.xlsx` | сама выгрузка: лист «Карточки к правке» (3 873 строки) + лист «Сводка» |
| `build-report.py` | скрипт, которым она собрана (детерминированный, запускается заново) |

## Зачем

Экспорт заказа WB FBS в OTS уходит с **нашим** артикулом — `vendor_code`
уровня SKU из ENSI PIM. Связка PIM ↔ WB возможна только по баркоду: другого
общего ключа нет, а `vendorCode` карточки на проде — это «модель/цвет»
(`GAS011429/коричневый`), товар по нему не опознать.

Если баркода нет в PIM, коннектор не отправляет заказ на склад и пишет
отклонение `unknown_sku`. Это осознанное поведение: пустой или чужой артикул в
WMS хуже остановленного заказа.

## Что внутри

| Класс | Строк | Что значит |
|---|---:|---|
| внутренний «2…» | 3 862 | префикс EAN-13 для внутреннего обращения; в PIM таких нет ни одного |
| битый | 11 | длина не 13 (`123`, `56-58`, серия `46012345678x`) — заведомо не баркод |

Разбивка по карточкам: **2 046 смешанных** (часть размеров на товарном GS1,
часть — нет; выделены жёлтым) и **989 полностью внутренних**.

Смешанные — приоритет. Там нормальный `vendorCode`, живой продаваемый товар, и
обычно испорчен один размер из нескольких: чаще всего 1 из 6, 1 из 4, 1 из 5.
Правка одного баркода снимает проблему целиком. У полностью внутренних
`vendorCode` тоже битый (`Леггинсы/size44/23/12/new1`) — похоже на тестовые
дубли, их скорее надо удалять, чем чинить.

## Как чинить

Привести баркод размера в ЛК ВБ к товарному EAN — тому же, что заведён в PIM.
Обойти это на стороне сервиса нечем: склад и OTS физически работают по
баркоду, а связать карточку с товаром иначе не получается — `vendorCode`
карточки живёт на уровне «модель + цвет», размер пришлось бы угадывать по
`techSize`, и PIM фильтра по нему не даёт.

## Источник и воспроизведение

Снимок каталога прод-кабинета от 2026-07-27 (82 228 карточек, 359 892
размеро-баркода), только чтение:
`platform-new/wbconnector/dev/catalog/wb-catalog-2026-07-27.jsonl.gz`.

```bash
python3 build-report.py \
  ../../platform-new/wbconnector/dev/catalog/wb-catalog-2026-07-27.jsonl.gz \
  wb-cards-with-unmappable-barcodes-2026-07-27.xlsx
```

Охват сверялся с прод-БД PIM 2026-08-25 по всему каталогу, не по выборке:
из 359 881 корректного баркода WB в PIM отсутствуют 3 883, то есть 1,08 %.
Настоящих товарных GS1 среди них всего 10 — покрытие 99,997 %. Подробный
разбор — `docs/superpowers/plans/2026-08-25-wbconnector-pim-identifiers.md`,
раздел «Пересечение баркодов PIM × WB».
