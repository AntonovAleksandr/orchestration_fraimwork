# ORCA-ACCEPT-FIX — доделать приёмку по следу

Задачи в Jira НЕТ, шаг перевода статуса пропустить. Репозиторий — этот
(development-platform), ветка `main`, коммитить прямо в неё.

**ЦЕЛЬ:** исправить три дефекта в приёмке по следу — ошибку `local` в `wait`, отсутствие отказа в `release` и неправильные expect-скрипты.

**КРИТЕРИЙ ГОТОВНОСТИ:** `bash -n` без ошибок, `verify OPSOMN002-289` вернёт НЕ ПРИНЯТО с перечнем лишних файлов, `verify customers-api-web-831 review` вернёт ПРИНЯТО, `release` отказывает при непройденной проверке.

Продолжение коммита `13fa524` «приёмка по следу с контролем через expect.sh». Основа
сделана: флаг `--expect`, `verify_expect()`, подкоманда `verify`, разделы в скиллах.
Три дефекта, из-за которых работает не всё.

## Дефект 1 — `local` вне функции ломает `wait` на ходу

Строки 786, 789, 790, 791 `scripts/gj/orchestrate.sh` объявляют `local` прямо в ветке
`wait)` оператора `case`, а это не функция. `bash -n` молчит, но на живом прогоне:

```
scripts/gj/orchestrate.sh: line 786: local: can only be used in a function
```

Проверка после `worker_done` из-за этого не выполняется вовсе — то есть главная часть
правки мертва. Убрать `local` (обычные присваивания) либо вынести блок проверки в
отдельную функцию. Второе чище: `check_done_dispatch <dispatch>`.

## Дефект 2 — `release` не отказывает

В постановке было: `release` обязан отказать по диспетчу, у которого `expect.sh` есть,
а последняя проверка не прошла; обход — `GJ_FORCE=1` с явным сообщением, что сдача
принята без следа. В `release_one()` ни `expect`, ни `verify` не упоминаются — отказа
нет. Сделать.

## Дефект 3 — показательный пример не работает

`.tasks/opsomn002-289/expect.sh` сравнивает с ревизией `main`:

```
$ scripts/gj/orchestrate.sh verify OPSOMN002-289
НЕ ПРИНЯТО
fatal: bad revision 'task-OPSOMN002-289-attempts-limit..main'
```

«НЕ ПРИНЯТО» здесь получено не потому, что в ветке лишние файлы, а потому что команда
упала. Это ложная тревога, которая выглядит как настоящая, — хуже, чем отсутствие проверки.

Правильный замер: репозиторий `platform/ensi/apps/connectors/webapi-connector`, целевая
ветка `release-26.09-release-26.10`, считать файлы в `git diff --name-only
origin/release-26.09-release-26.10...task-OPSOMN002-289-attempts-limit`, ожидание — 4.
Клоны `platform/*` поверхностные: без `git fetch --unshallow` сравнение врёт. На момент
постановки в ветке 8 файлов, то есть честный ответ — НЕ ПРИНЯТО с перечнем лишних.

Так же проверить второй пример (`.tasks/review-customers-api-web-831/expect.sh`): там
ожидается «веток без нашего ответа ноль», и сейчас это правда — он обязан давать ПРИНЯТО.
Если даёт другое — чинить команду, а не ожидание.
