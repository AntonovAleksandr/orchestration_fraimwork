# Комментарии в коде

<!-- Файл .md, а не .mdc: Claude Code читает из .claude/rules только *.md. -->

Комментарий нужен, когда из кода **не видно почему** и без этого знания следующий читатель —
человек или модель — ошибётся. Всё остальное в код не пишется.

## Писать

- **Почему так, а не очевидным способом**, если очевидный ломается:
  `// V1 ждёт link, OMS в widget-режиме отдаёт confirmationToken — читаем оба`.
- **Реальную опасность**: необратимость, деньги, прод-данные, гонку, порядок выкатки:
  `// Откат бонусов один раз на заказ: повторный вызов вернёт их дважды`.
- **Внешний контракт, которого нет в коде**: опечатка в чужом API, формат другой системы,
  ограничение поставщика — со ссылкой на источник (задача, страница, файл:строка).

## Не писать

- Ход работы: «сначала пробовал X», «исправлено по ревью», «замер 25.09 показал…».
  Этому место в коммите, описании запроса или `docs/tasks/`.
- Пересказ кода: `// увеличиваем счётчик`, docblock, повторяющий имя и типы.
- Закомментированный код, «TODO» без задачи, благодарности, подписи агента.
- Абзацы. Больше трёх строк — признак, что это документ, а не комментарий: вынести в
  `docs/` и оставить в коде одну строку со ссылкой.

## Форма

- Одна-три строки, на языке окружающих комментариев файла.
- Утверждение о коде, которое останется верным, пока код не изменится. Даты и номера
  задач — только если без них не проверить («см. OPSOMN002-373», не «сделано 30.09»).
- Ключевое слово в начале, чтобы находилось поиском и моделью: `ВАЖНО:`, `Контракт:`,
  `Почему:` — только когда это действительно так.

## Старые комментарии-истории — убирать попутно

Правишь код — чисти комментарии **в том, что меняешь**: функции, блоке, рядом стоящих строках.

- История, пересказ, закомментированный код — удалить.
- Внутри есть настоящее предупреждение или контракт — оставить его одной строкой, остальное
  удалить; длинное объяснение, которое ещё нужно, — в `docs/`, в коде ссылка.
- Не понятно, нужен ли комментарий, — оставить и спросить в описании запроса.

Чужие файлы и участки, которых правка не касается, ради чистки не трогать: такой дифф
труднее ревьюить и он конфликтует с соседними ветками. Массовую чистку — отдельным
запросом, по просьбе.

Проверка перед коммитом: убрать комментарий мысленно — станет ли следующий читатель
ошибаться? Нет — удалить.
