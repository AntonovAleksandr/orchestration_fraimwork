# Ревью: каталог типовых дефектов

Источник: руководство ревью Олейникова (gj-ai-workspace, `payload/aiassistant/guides`), нормализовано под этот воркспейс 2026-10-02.

Дефекты, которые уже находились в MR рабочего пространства. У каждого — признак в коде,
контрпример и исправление. Ссылка в конце строки — заметка с разбором конкретного случая.
Новый повторяющийся дефект дописывается сюда одной записью.

## Состояние и повторы

**Публикация по разнице снимков.** Признак: `snapshot()` до изменений, `snapshot()` после,
событие — если отличаются, всё в одном запросе. Контрпример: данные записаны, отправка
упала → 500 → повтор → снимки равны → событие не уйдёт никогда. Исправление: outbox или
флаг «не опубликовано» на сущности, публикация после коммита с повтором.

**Одна отметка на две операции.** Признак: два внешних вызова подряд, флаг «сделано» после
обоих. Контрпример: первый прошёл, второй упал → повтор повторяет первый → внешняя система
отвечает «уже сделано» как ошибкой → сценарий заблокирован навсегда. Исправление: отметка
на каждую операцию сразу после неё.

**«Лучшее усилие» на отметке идемпотентности.** Признак: `try { mark(); } catch { log; }`
после необратимой операции. Контрпример: отметка не записалась → повтор или отмена решают,
что операции не было. Исправление: явная машина состояний, запись намерения до вызова.

**Статус раньше деталей.** Признак: сначала финальный статус сущности, потом её позиции.
Контрпример: позиции упали → повтор получает «статус уже установлен» → позиции не допишутся.
Исправление: финальный статус — последним шагом; повтор доводит детали.

**Полное состояние без версии.** Признак: событие несёт весь состав, код замещает хранимое,
`updated_at` события не сравнивается. Контрпример: старое событие после нового удаляет
действующий документ. Исправление: хранить версию применённого события, пропускать старые;
ключ сообщения — id сущности.

**Порядок только внутри пакета.** Признак: «поздний отзыв перекрывает строку» считается по
строкам одного запроса. Контрпример: отклонённая строка приходит повторно в следующем пакете
после отзыва и восстанавливает связь. Исправление: сравнивать с сохранённым моментом.

## Тихие отказы

**Отсутствие поля как пустое значение.** Признак: `$payload->list ?? []` с последующим
замещением. Контрпример: сообщение старого формата очищает данные. Исправление: различать
`array_key_exists` и пустой массив.

**Глушение внешних ошибок по имени.** Признак: список кодов «уже выполнено», применяемый
ко всем операциям. Контрпример: «по купону уже была продажа» — по другому заказу, а мы
ответили успехом. Исправление: пары (операция, код), сверка объекта операции.

**Значения по умолчанию на обязательных полях.** Признак: `?? 0`, `?? ''`, `?? 1` на цене,
id, количестве. Контрпример: касса получает позицию с ценой 0 и ответ 200.

**Молчаливое исправление входа.** Признак: `min(запрошено, есть)`, суммирование дублей,
фильтр невалидных элементов без лога. Исправление: отказ с отдельным кодом ошибки.

**Чёрный список вместо белого.** Признак: «запрещено на COMPLETED и CANCELLED». Любой новый
статус становится разрешённым. Исправление: перечень разрешённых состояний и типов.

## Конкурентность и БД

**Блокировка несуществующей строки.** Признак: `lockForUpdate()->first() ?? new Model()`
с комментарием «иначе параллельные вызовы заведут дубль». Блокировать нечего, защищает
только unique — второй вызов падает. Исправление: `upsert` / `ON CONFLICT`.

**Read-modify-write JSON-атрибута.** Признак: прочитали атрибут, изменили массив, записали
целиком. Контрпример: два параллельных запроса затирают отметки друг друга. Исправление:
блокировка по сущности, запись отдельных полей.

**Транзакция на строку при семантике пакета.** Признак: `transaction()` внутри цикла,
а замещение и публикация — после цикла. Исправление: транзакция на пакет.

## Выкатка

**Новый маппинг индекса.** Признак: имя индекса содержит хеш настроек, чтение по тому же имени.
Контрпример: при обратном порядке выкатки витрина читает пустой индекс до конца переиндексации.
Исправление и порядок — `gj-rollout-safety` §2.

**Потребитель включён раньше поставщика.** Признак: «кассу не переключать, пока OMS не
примет поля» только в описании MR. Исправление: флаг или проверка готовности, запись
порядка выкатки в план задачи.

## Тесты и документация

**Тест проходит по другой причине.** Признак: `atLeast()->once()` на вызове, который
делает и соседний шаг. Исправление: проверять именно путь исправления.

**Фикстура удобнее прода.** Признак: в фикстуре заполнено поле, которое в проде пусто,
или формат дат не как у источника. Исправление: фикстура по реальному сообщению.

**Неопределённая переменная в редкой ветке.** Признак: переменная из соседнего метода
в контексте лога. В Lumen/Laravel `error_reporting(-1)` превращает notice в исключение —
падает именно защитная ветка. Исправление: phpstan по изменённым файлам, тест ветки.

**Комментарий, обещающий несуществующее.** Признак: «от повтора защищает следующий шаг»,
«снимает риск». Ревьюер проверяет обещание по коду.

## Где правило для автора

Каталог — сторона ревьюера. Те же классы со стороны автора правки, с самопроверкой перед сдачей:
состояние, повторы, конкурентность, события — `gj-retry-safe-writes`; тихие отказы и коды
ошибок — `gj-fail-loud-boundaries`; деньги, время, номера — `gj-value-precision`; архитектура,
комментарии, тесты, описание MR — `gj-change-hygiene`; выкатка, индексы, задания k8s,
ключи сред — `gj-rollout-safety`. Новый повторяющийся дефект дописывать
сюда одной записью и в соответствующий скилл автора.
