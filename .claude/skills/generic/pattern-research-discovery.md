**Категория:** [PATTERNS]

## 📋 Описание

**Явный паттерн исследования** - единственный способ работать исследователю.

Все исследователи **ДОЛЖНЫ ВСЕГДА** следовать этим 5 шагам. Нет импровизации.

---

## 🎯 5 обязательных шагов

### 1️⃣ ПОИСК (Search & Identify)

**Что делать:**
- Определить ключевые слова/сущности для поиска
- Найти их в источнике
- Выписать релевантные куски **с цитатами**

**Пример (Conf-researcher):**
```
Ключевые слова: "контракт", "OMS", "Integration", "API"

Найдено:
- "Контракт между OMS и Integration: ..." (ссылка)
- "API версия должна быть X" (ссылка)
```

**Пример (Code-researcher):**
```
Ключевые слова: "enum OrderStatus", "handler", "dependency"

Найдено:
- OrderStatus enum в файле X:Y
- Handler в классе Z
```

---

### 2️⃣ ВАЛИДАЦИЯ (Validate Source)

**Что проверять:**

| Проверка | Как | Пример |
|---|---|---|
| **Дата** | Актуально ли? (не старше 2 недель) | ✅ "Обновлено 2026-10-05" |
| **Branch/версия** | Правильная ветка? | ✅ "Branch: main" или ❌ "Branch: develop (может быть unstable)" |
| **Авторство** | Кто писал? Доверяем? | ✅ "Автор: архитектор" или ⚠️ "Автор: неизвестно" |
| **Консистентность** | Совпадает ли с другими источниками? | ✅ "Совпадает с code-researchers" |

**Отметить:**
- ✅ Надёжный источник
- ⚠️ Потенциально устарелый
- ❌ Конфликт с другими источниками

---

### 3️⃣ КОНФЛИКТЫ (Detect Conflicts)

**Что искать:**

1. **Внутри этого источника:**
   - Есть ли противоречия?
   - Пример: "API версия X" vs "API версия Y" в одном файле

2. **С другими исследователями:**
   - Conf-researcher говорит X?
   - Code-researcher говорит Y?
   - Это конфликт? Нужно отметить [CONFLICT]

**Как отметить:**
```
[CONFLICT] 
Conf говорит: "Контракт должен быть в OMS"
Code говорит: "Контракт в Integration"
→ Нужна уточнение!
```

---

### 4️⃣ ПОЛНОТА (Completeness Check)

**Что проверять:**

- ✅ Хватает ли информации для понимания?
- ❓ Есть ли пробелы? Где именно?
- 🚨 Нужна ли доинформация?

**Как отметить:**

```
✅ Покрыто:
  - ТЗ требование ясно
  - API контракт описан
  - Edge-cases упомянуты

❓ Пробелы:
  - Нет информации о версионировании
  - Не ясно как обрабатывать ошибки

[BLOCKER] Необходимо:
  - Уточнение: версия API какая?
```

---

### 5️⃣ ВЫВОД (Output)

**Структурированный отчёт, готовый для Аналитика:**

```markdown
# [Research Type] Исследование

## Ключевые факты
- факт 1 (цитата + ссылка)
- факт 2 (цитата + ссылка)
- факт 3 (цитата + ссылка)

## Валидность источников
- ✅ Conf: актуально, надёжно
- ⚠️ Code-OMS: может быть неполно
- ✅ Logs: свежие данные

## Конфликты обнаружены?
- [CONFLICT] Conf vs Code: разные версии контракта
- ✅ Нет других конфликтов

## Полнота информации
✅ Покрыто: основное требование, API, ошибки
❓ Пробелы: версионирование

## Вопросы для Аналитика
- [BLOCKER] Какая версия API в продакшене?
- [NB] Как обрабатываем случай X?

## Ссылки на источники
- [Conf]: https://...
- [Code]: path/to/file.ts:line
- [Logs]: grep "keyword" stage-logs.txt
```

## ✨ Важные правила

### Правило 1: ВСЕГДА 5 шагов
- Нет сокращений
- Нет импровизации
- Даже если "очевидно" - пройди все 5 шагов

### Правило 2: ЦИТАТЫ с ссылками
- Не писать "я понял что..."
- Писать "вот цитата: '...' (ссылка)"
- Без ссылок - вывод не принимается

### Правило 3: ЯВНЫЕ конфликты и пробелы
- Не скрывать проблемы
- Отметить [CONFLICT] если есть сомнения
- Отметить [BLOCKER] если нужна информация

### Правило 4: ЧИТАЕМО и СТРУКТУРИРОВАНО
- Markdown форматирование
- Заголовки, списки, таблицы
- Аналитик быстро должен понять вывод

### Правило 5: ДО ВЫВОДА - проверка качества
- Перед выводом: пройди все 5 шагов еще раз
- Все ли факты подтверждены?
- Все ли конфликты отмечены?
- Хватает ли полноты?

## 🎓 Примеры выполнения

### Пример 1: Conf-researcher (ТЗ и требование)

```markdown
# Confluence Исследование: требования OPSOMN002-XXX

**Ключевые факты:**
- "Новый статус SHIPPED_TO_CUSTOMER" (цитата из Conf)
- "Должен быть обработан в OMS и Integration" (цитата)
- "Visible в UI для пользователя" (цитата)

**Валидность:**
- ✅ Confluence: обновлена 2026-10-05, от архитектора

**Конфликты:**
- ❌ Нет конфликтов обнаружено

**Полнота:**
✅ ТЗ ясно: что нужно делать
❓ Пробелы: нет AC (acceptance criteria)

**Вопросы:**
- [NB] Нужны ли specific AC? Или "статус видимый" достаточно?
```

### Пример 2: Code-researcher (структура)

```markdown
# Code Исследование: OrderStatus enum в OMS

**Ключевые факты:**
- OrderStatus enum в platform/starfish24/core/Order/OrderStatus.java:42
- Текущие значения: PENDING, PROCESSING, SHIPPED (всего 34)
- Есть handler для каждого статуса

**Валидность:**
- ✅ Code: main branch, последний коммит от 2026-10-03
- ✅ Файл актуален: нет TODO/DEPRECATED

**Конфликты:**
- ❌ Нет конфликтов

**Полнота:**
✅ Enum структура ясна
✅ Handlers для каждого статуса есть
❓ Пробелы: нет документации как добавлять новый статус

**Вопросы:**
- [NB] Есть ли pattern для добавления нового статуса?
```
