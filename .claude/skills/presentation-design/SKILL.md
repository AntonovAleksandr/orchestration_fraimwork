# Подготовка презентаций

Презентация — это история, которую слушатель смотрит, а не читает. Текст говорит докладчик
(заметки), слайд показывает одну мысль и помогает удержать место в истории.

## 1. История до дизайна

1. **Сначала заголовки.** Выпиши все заголовки слайдов подряд в одной грамматике. По одним
   заголовкам должно быть понятно, о чём доклад. Покажи этот список автору до сборки.
2. **Разделы и главы.** 3–5 разделов, в каждом 2–3 главы. Раздел открывается слайдом-разделителем
   со списком его глав. На каждом слайде видно, где мы: плашка раздела вверху, полоса прогресса внизу.
3. **Глава = пара слайдов.** «Проблема» (тёмный, мокап ситуации) → «Решение» (светлый: что сделали,
   технологии и зачем, почему работает). Формат автора: «столкнулся → придумал → взял технологию
   для того-то».
4. **Ритм.** Вопрос в зал каждые 5–7 слайдов отдельным слайдом. Слайд-высказывание после тяжёлого
   блока. В финале вернуться к вопросу из начала.
5. **Конец истории.** Текущее устройство (схема), что умеет (функции), предложения (починить /
   измерить / развить), финальный вопрос.

## 2. Иерархия внимания

Взгляд идёт в таком порядке: **движение → контраст → мелкие детали.** Управляй смыслом кадра
этим порядком.

- **Движение — одно на слайд.** Анимируется только главный элемент: большое число, вывод,
  мокап. `data-build-in="rise|pop|fade"` работает только у закреплённых (`position:absolute`)
  элементов, поэтому главный элемент закрепляй.
- **Контраст — второй.** Самое тёмное на светлом или акцент на тёмном — то, что прочтут после
  движения. Одно контрастное пятно на слайд.
- **Детали — третьи.** Подписи, источники, номера глав: Roboto Mono 24 px, приглушённый цвет.

## 3. Сетка и ритм

- Холст 1920×1080, поля 128 px по бокам, 96 px сверху, 160 px снизу при полосе прогресса.
- Шаг отступов 8: 16, 24, 32, 48, 64. Внутри карточки 24–40, между блоками 32.
- **Заголовок на одной высоте** на всех контентных слайдах: одинаковая шапка (плашка раздела +
  название компании из настроек), под ней надпись темы и заголовок. Колонку не центрировать, тело растягивать вниз.
- Нижняя полоса: глава слева, точки разделов справа, `bottom:64px`, высота 32.
- Текст колонкой 800–1000 px, а не во всю ширину.

## 4. Визуальная система (фирменный шаблон + Material 3 + Cupertino)

| Роль | Значение |
|---|---|
| Тёмная поверхность | `#141414` — слайды проблем, разделители-высказывания |
| Светлая поверхность | `#FAFAF7` — слайды решений и итогов |
| Контейнеры (M3 tonal) | `#EFEEE9`, высокий `#E6E4DE`, контур `#D9D7D0` |
| Акцент «проблема» | оранжевый акцент `#FF7238`; текст на светлом `#B8400C`, на тёмном `#FF8A55` |
| Акцент «решение» | синий `#2E5BFF`; текст на светлом `#1F45D6` |
| Статусы (пастель) | хорошо `#D9EAD3`, плохо `#F4CCCC`, нейтрально `#C9DAF8`, заметка `#FFF2CC` |

- **Material 3:** тональные контейнеры вместо обводок и теней, радиусы 16 / 28, крупная
  пилюля-кнопка для вывода.
- **Cupertino:** сгруппированный список (белые строки на сером, разделители 1 px, радиус 20),
  переключатель-сегменты для разделов, «лист» с ручкой для вопроса в зал.
- **Шрифты, три роли:** Unbounded — только числа и номера разделов; Manrope — заголовки и текст;
  Roboto Mono — надписи темы, подписи, код. Шкала: 200 / 120 / 64 / 40 / 28 / 24.
- **Цвет кодирует смысл и держится всю колоду:** оранжевый = проблема, синий = решение.
- Градиент — один раз, на обложке. Без смайликов, без карточек с цветной полосой слева.

## 5. Типы слайдов

Колода собирается из 8–10 типов. Один тип — одна разметка. Типы чередуются, чтобы не было скучно.

| Тип | Когда | Главный (анимированный) элемент |
|---|---|---|
| Обложка | начало | заголовок |
| Оглавление | после обложки | — |
| Разделитель | начало раздела | номер раздела |
| Проблема · мокап | ситуация видна в интерфейсе | мокап (телефон, терминал, MR, окно) |
| Проблема · число | проблема измерима | большое число |
| Проблема · цитата | проблема в словах человека | цитата |
| Решение · технологии | новые инструменты | вывод «почему работает» |
| Решение · схема | новый процесс | последний узел схемы |
| Вопрос в зал | раз в 5–7 слайдов | лист с вопросом |
| Итог · сетка | что умеет система | — |

Иллюстрации — живые интерфейсы (телефон, терминал, окно кода, MR, дашборд), свёрстанные текстом.
Выдуманные данные в мокапе подписывать словом «пример» или «иллюстрация».

## 6. Текст

- На слайде не больше трёх блоков. В блоке до 12 слов. Абзацы — в заметки докладчика.
- Заголовок до 38 символов в одну строку при 64 px, или две строки.
- Выделять словом, цветом или весом, а не новым размером.
- Цифры — только измеренные или взятые из источника; источник подписывать мелко внизу.
- Номера коммитов на слайды не выносить: даты и названия этапов вместо хэшей.
- Заметки докладчика — полный текст для чтения короткими фразами, с пометками
  [Пауза], [Спросить зал].

## 7. Чек-лист перед публикацией

- [ ] Заголовки подряд рассказывают историю
- [ ] На каждом слайде видно раздел и главу
- [ ] Одно движение и одно контрастное пятно на слайд
- [ ] Заголовок на одной высоте на всех контентных слайдах
- [ ] Нет текста меньше 24 px и абзацев больше двух строк
- [ ] Цвет проблемы и решения не перепутан
- [ ] Все числа имеют источник, иллюстрации подписаны
- [ ] Вопрос в зал хотя бы каждые 7 слайдов, финал возвращает к началу
- [ ] У каждого слайда есть заметки докладчика
- [ ] Поверхность отличается от фона: контраст не ниже 1.15 или обводка 2 px. Тень на почти белом фоне карточку не выделяет. На тёмном фоне карточки #2A2A28, а не #1F1F1D
- [ ] Текст не ниже 4.5:1 к своему фону, включая подписи «пример» внутри макетов
- [ ] Между потоком и закреплённой плашкой не меньше 40 px; соседние закрашенные блоки не вплотную
- [ ] Не больше ~350 знаков содержания на слайд без шапки и подвала; лишнее — в заметки
- [ ] Проверка автоматом, а не только глазами: пересечения, выход за блок, контраст, зазоры, плотность

## 8. Где собирать

Колоду для показа и экспорта в PPTX/PDF собирай артефактом типа Slides: HTML-слайды с
инлайн-стилями, логотипы и картинки загружаются как ассеты. Pptx через python-pptx из простых
фигур выходит серым и без иллюстраций — этот путь только когда нужен именно редактируемый .pptx
по шаблону.
