# Проверка замечаний ревью перед публикацией

Загружать после того, как ревьюер подготовил находки, и до любой публикации в обсуждения запроса на слияние.
Публикация без проверки запрещена: ядро не опубликует находку без вердикта.

Цель: каждое замечание подтвердить, отклонить или вынести человеку как вопрос — по фактам из кода и постановки,
а не по впечатлению.

## Вход

- Находки из отчёта ревью: номер, приоритет, место `путь:строка`, проблема, почему, решение.
- Версия кода, по которой ревью: коммит (`Вершина на ревью`).
- Постановка задачи: критерии приёмки и разделы, которые относятся к решению.

## Процедура на каждое замечание

1. **Место существует.** Строка есть в версии ревью (`framework/core/git_source.py`, `line_exists`). Нет — вердикт
   `rejected`, причина «место не найдено в версии ревью». Это не спор о сути, а ошибка ссылки.
2. **Код делает то, что написано.** Прочитать строку и окружение (функцию целиком), проверить утверждение замечания
   по коду. Утверждение «не обрабатывается» проверяется поиском вызовов, а не предположением.
3. **Замечание касается постановки.** Найти критерий приёмки или раздел постановки, которому оно противоречит или
   который не выполняет. Нет связи с постановкой — `rejected`: «вне постановки, основание …». Не путать с общим
   улучшением стиля: это низкий приоритет или отклонение.
4. **Приоритет адекватен.** Блокер — только если нарушен критерий или возможна порча данных. Иначе понизить или
   отклонить с причиной.
5. **Неоднозначно.** Если постановка молчит или два пункта противоречат друг другу — `question` с вопросом человеку:
   что именно спросить, какой вариант принимаем по умолчанию, что меняется при другом ответе.

## Вердикт

Для каждого замечания записать:
- `confirmed` — `ref`: критерий или раздел постановки и строка кода, подтверждающая замечание;
- `rejected` — `reason`: что именно неверно (место, код, постановка);
- `question` — `reason`: вопрос человеку с вариантами и значением по умолчанию.

Без доказательства вердикт не записывается. Фраза «кажется» не доказательство.

## Чего не делать

- Не править код, не открывать обсуждения, не менять отчёт ревью.
- Не заводить задачи. Вынесение доработки из фичи — только с согласия человека, с обоснованием.
- Не подтверждать замечание только потому, что оно записано в отчёте.

## Результат

Список вердиктов по всем находкам, список вопросов человеку, перечень отклонённых с причинами. Этот результат
передаётся в публикацию. Пустой список находок — отчёт «замечаний нет», публикация ничего не добавляет.
