# Работа над проектом через Orca

Orca даёт готовый слой оркестрации. Этот скилл — не замена её скиллам, а **раскладка**:
что из Orca брать на каждой фазе задачи GJ, какой скилл проекта при этом обязателен
и какие ошибки уже допускались.

Экономика и фазы — `gj-task-orchestration`. Корректность правки — `gj-task-execution`.
Измерение — `gj-session-analytics`.

## Почему делегировать работникам Orca, а не подагентам

Замерено 15.09.2026: **ходы внутренних подагентов (инструмент `Agent`) не логируются
вообще** — ни в `~/.claude/projects`, ни где-либо ещё. 74 делегирования за два месяца
стоили неизвестно сколько.

**Работники Orca — обычные сессии** и пишутся в журналы полностью: найдено 10 таких
сессий на 221 млн токенов, с разбивкой по рабочим деревьям. Перевод делегирования на
Orca делает цену делегирования измеримой — это главный довод, важнее удобства.

Проверить: `scripts/gj/stats.py --workers`.

## Как запускать

Короткий путь — обёртка, которая вписывает вызовы скиллов первой строкой реплики
(подбор по описанию не работает: скиллы грузятся в 0,17% ходов):

```bash
scripts/gj/orchestrate.sh task   OPSOMN002-123 "заголовок"
scripts/gj/orchestrate.sh review <адрес запроса>
scripts/gj/orchestrate.sh done   OPSOMN002-123
scripts/gj/orchestrate.sh list | say | read | wait | go
```

Надзираемый путь — когда нужен веер с ожиданием результата. Через `orchestration`:
создать Run, запустить работников, ждать `worker_done`. **Спецификация задачи работнику
обязана называть пять вещей** (это договор скилла `orchestration`): цель, изменение,
ограничения, границы владения, наблюдаемый признак готовности.

В спецификацию всегда добавлять строку: «Загрузи скиллы <перечень> до любых действий» —
иначе работник начнёт без них, как показывает замер.

## Ошибки, которые уже допускались

Каждая стоила переделки. Проверять до того, как делать вывод.

- **Дифф из интерфейса GitLab при большом наборе приходит пустым.** На `cms!7` пустыми
  пришли 566 файлов из 587. Брать локальным git: `scripts/gj/mr-brief.py` уже так делает.
- **Утверждение «поле есть в N местах» без прогона команды.** Дважды оказалось неверным.
  Находка обязана нести команду, которая её доказывает, и её фактический вывод.
- **Вывод об ущербе из чтения кода.** «OMS сохраняет нулевые строки» — по коду да, по
  данным прода ни одной. Замер через `data_pg_query` до оценки серьёзности, не после.
- **Клоны под `platform/` поверхностные.** `merge-base`, ahead/behind и cherry-pick врут
  до `git fetch --unshallow`.
- **Слияние в `master` ≠ прод.** В ENSI прод-деплой ручной. Ветки — только из
  `docs/deploy/branch-registry.md`.
- **Полный кадр экрана в контексте** — 390 КБ ≈ 97 тыс. токенов, и он перечитывается на
  каждом следующем ходе. 219 таких чтений дали 99% всего объёма чтения файлов.
- **Двойной счёт в аналитике.** Один ответ пишется несколькими записями с общим usage;
  без склейки по `requestId` расход завышается вдвое.

## Контроль вёрстки: дерево против снимка

Две разные проверки, и путать их дорого.

- **Состав и расположение** — `orca emulator ax --json`: дерево доступности, до 500 узлов,
  координаты нормированы 0..1. Структурный ответ на несколько тысяч токенов, утверждения
  точные («кнопка есть, лежит в нижней трети»).
- **Внешний вид** — `scripts/gj/golden.sh check`: сверка с эталоном числами, картинка
  только при расхождении и только вырезкой.

Дерево не видит цвета, отступы и шрифт; снимок не даёт точных утверждений о составе.
Начинать с дерева — оно дешевле и даёт проверяемые утверждения.

## Аналитика агентов и работников

```bash
scripts/gj/stats.py --workers        # работники orca: расход по деревьям
scripts/gj/stats.py --skills         # загрузки скиллов, делегирования, цена ревью
scripts/gj/stats.py --skill-effect   # сессии со скиллом против сессий без него
scripts/gj/stats.py --compare 14     # период против предыдущего
```

**Как читать `--skill-effect`.** Разница «со скиллом дороже» сама по себе ничего не значит:
скиллы грузят на сложных задачах. Смотреть надо **тренд одного скилла между периодами**,
а не сравнение скиллов между собой. Скилл работает, если при его росте использования
падает расход **на задачу** — не общий.

Ресурсы хоста: `orca diagnostics memory --json` даёт память по каждой сессии с привязкой
к рабочему дереву. Жёсткого лимита ОЗУ на процесс в macOS нет (`claude` — нативный бинарь,
cgroups отсутствуют), поэтому оркестратор ограничивает число сессий и свободную память
на входе: `GJ_MAX_AGENTS`, `GJ_MIN_FREE_MB`, обход `GJ_FORCE=1`.

## Чтобы скиллы не терялись

Три независимых механизма, потому что каждого по отдельности мало:

1. **Оркестратор** вписывает вызовы скиллов первой строкой стартовой реплики.
2. **Хук `UserPromptSubmit`** (`.claude/hooks/skill-reminder.sh`) подставляет имя скилла
   по ссылке на Jira, по «проведи ревью», «задача выполнена», «замерь».
3. **Спецификация работнику** содержит перечень скиллов явной строкой.

Подбор по описанию как единственный механизм не работает: из 54 русских триггерных фраз
в 1 438 репликах встретились шесть.
