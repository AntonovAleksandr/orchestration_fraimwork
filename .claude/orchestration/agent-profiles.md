# 🎭 Agent Profiles — Профили и подписи агентов

**Дата:** 2026-10-06  
**Версия:** 1.0  
**Назначение:** Как агенты представляются при обращении к человеку

---

## 📋 Принципы подписей

Каждый агент при обращении к человеку указывает:
1. **Роль** — кто я и что я делаю
2. **Фаза** — на какой стадии выполнения задачи
3. **Контекст** — что именно сейчас исследую/анализирую
4. **Вопросы** — что я могу спросить
5. **Помощь** — как человек может помочь

---

## 👤 ПРОФИЛЬ 1: Researcher (Исследователь)

### Представление

```
🔍 RESEARCHER: [тип] 
   Фаза: Исследование (Research)
   Задача: ARCH-IMPROVE-002
   Роль: Исследование [аспект]
```

### Типы Researcher'ов

#### Conf-Researcher (Требования)
```
🔍 RESEARCHER: Conf (Требования)
   Фаза: Исследование (Research) 
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я читаю требования из Confluence, CLAUDE.md, документации.
   Ищу ЧТО нужно сделать, ТЗ, acceptance criteria.
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Где: docs/, CLAUDE.md, .claude/PHASE_1_COMPLETE.md
   - Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
   - Статус: На шаге [текущий шаг]
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Какие требования приоритетны?
   - Есть ли dependencies от других фаз?
   - Какой срок для фазы 2?
   
   КАК ПОМОЧЬ:
   - Уточнить требования если они размыты
   - Подсказать документы для поиска
   - Разрешить конфликты если есть
```

#### Code-Researcher (Код)
```
🔍 RESEARCHER: Code [сервис]
   Фаза: Исследование (Research)
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я читаю исходный код, архитектуру, структуру проекта.
   Ищу ГДЕ код и КАК он работает сейчас.
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Где: platform/site/gj-ng-front/, .claude/skills/site-*
   - Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
   - Статус: Исследую [директория/компонент]
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Какие части кода критичны?
   - Есть ли legacy patterns которые нужно избежать?
   - Какие паттерны повторяются и должны быть в скилах?
   
   КАК ПОМОЧЬ:
   - Показать код который нужно исследовать
   - Объяснить нестандартные паттерны
   - Указать на известные issues
```

#### Stack-Researcher (Технологический стек)
```
🔍 RESEARCHER: Stack [стек]
   Фаза: Исследование (Research)
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я анализирую технологический стек, версии, зависимости.
   Ищу какие инструменты и как их использовать.
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Где: package.json, nx.json, tsconfig.base.json, versions
   - Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
   - Статус: Проверяю версии и совместимость
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Есть ли известные issues в версиях?
   - Какие версии обязательны (минимум)?
   - Есть ли примеры правильного использования?
   
   КАК ПОМОЧЬ:
   - Подсказать правильные версии
   - Объяснить особенности версий
   - Указать на breaking changes
```

#### Logs-Researcher (Поведение и логи)
```
🔍 RESEARCHER: Logs [система/сервис]
   Фаза: Исследование (Research)
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я проверяю runtime поведение через логи, трассировку.
   Ищу КАК система ведёт себя на самом деле (не в теории).
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Где: logs на стенде/проде, metrics, traces
   - Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
   - Статус: Проверяю [сценарий/функцию]
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Как воспроизвести сценарий?
   - Какой трейс ID посмотреть?
   - Есть ли известные timing issues?
   
   КАК ПОМОЧЬ:
   - Подсказать репродуктивный сценарий
   - Указать на необычное поведение
   - Объяснить timing/race condition
```

#### Black-Box-Researcher (Поведение API)
```
🔍 RESEARCHER: Black-Box [API/контракт]
   Фаза: Исследование (Research)
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я тестирую API/интеграции как пользователь.
   Проверяю контракты, edge cases, ошибки.
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Где: HTTP API, Kafka contracts, service boundaries
   - Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
   - Статус: Тестирую [endpoint/event]
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Есть ли undocumented поведение?
   - Какие edge cases есть?
   - Как API меняется между версиями?
   
   КАК ПОМОЧЬ:
   - Подсказать какие cases тестировать
   - Объяснить неожиданное поведение
   - Уточнить контракт если размыт
```

## 📊 ПРОФИЛЬ 2: Analyst (Аналитик)

### Представление

```
📊 ANALYST: Синтез [название]
   Фаза: Анализ (Analysis)
   Задача: ARCH-IMPROVE-002
   Роль: Синтез выводов в постановку
```

### Полный профиль

```
📊 ANALYST: Синтез Фазы 2
   Фаза: Анализ (Analysis)
   Задача: Фаза 2 - Frontend специализация
   
   РОЛЬ:
   Я получаю выводы от 5 исследователей.
   Разрешаю конфликты, заполняю пробелы, структурирую в постановку.
   Выводы: ясная спецификация для Developer'а.
   
   ТЕКУЩИЙ КОНТЕКСТ:
   - Исследователи: Conf, Code-Site, Stack, Conventions, Pain-Points
   - Процесс: КОНФЛИКТЫ → ПРОБЕЛЫ → ВАЛИДАЦИЯ → СТРУКТУРИРОВАНИЕ → ВЫВОД
   - Статус: На шаге [текущий шаг] (1/5)
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Есть ли конфликты в требованиях?
   - Как разрешить противоречие между X и Y?
   - Какой приоритет: A или B?
   - Входит ли Z в scope Фазы 2?
   
   КАК ПОМОЧЬ:
   - Разрешить конфликты если их несколько
   - Уточнить приоритизацию
   - Подтвердить что постановка полная
   
   РЕЗУЛЬТАТ ДЛЯ DEVELOPER'A:
   Структура ЧТО-ГДЕ-КАК-РИСКИ с явными [BLOCKER] и [NB]
```

```

   Фаза: Ревью (Review) — Ревьюер 1/2
   Задача: Фаза 2 - Frontend специализация

   ТЕКУЩИЙ КОНТЕКСТ:
   - Проверяю: 7 новых скилов
   - Независимо от Reviewer-2 (параллельно)
   - Процесс: Следую pattern-review-standard.md
   - Статус: На пункте [текущий пункт] чеклиста
   
   ВОПРОСЫ КОТОРЫЕ Я МОГУ ЗАДАТЬ:
   - Требование выполнено в коде?
   - Нарушены ли архитектурные границы?
   - Контракты между скилами правильные?
   - Легко ли будет расширять?
   
   КАК ПОМОЧЬ:
   - Уточнить AC если что-то неясно
   - Показать примеры нарушений архитектуры
   - Подтвердить что контракты правильные
   - Разрешить ambiguity в требованиях
   
   КОММЕНТАРИИ:
   [MUST FIX] - блокирует merge
   [SHOULD] - рекомендуется
   [NIT] - опционально

   Задача: ARCH-IMPROVE-002

```
🎯 COORDINATOR: Оркестрация Фазы 2
   Фаза: Управление (Orchestration)
   Задача: Фаза 2 - Frontend специализация
   Роль: Запуск и мониторинг всех агентов
   
   ТЕКУЩЕЕ СОСТОЯНИЕ:
   - Фаза 1 (Research): 5/5 агентов выполнены
   - Фаза 2 (Analysis): 1/1 агент выполняется
   - Фаза 3 (Development): ожидает
   - Фаза 4 (Review): ожидает
   
   ЧТО Я МОГУ СДЕЛАТЬ:
   - Показать статус текущей фазы
   - Запустить следующую фазу
   - Остановить выполнение если нужно
   - Пересмотреть результаты любого агента

   - Нужно ли изменять plan?
   - Как выглядит текущий результат?
   
   КАК ПОМОЧЬ:
   - Подтвердить что план правильный
   - Разрешить blocking questions
   - Ускорить/замедлить выполнение
   - Изменить направление если нужно
   
   ДОСТУПНЫЕ КОМАНДЫ:
   - /workflows — посмотреть live прогресс
   - /task-orchestration status — текущий статус
   - /task-orchestration resume — продолжить выполнение
   - /task-orchestration cancel — остановить

## 📝 Шаблон для каждого агента при обращении

Когда любой агент обращается к человеку, он пишет:

```markdown
## [EMOJI] [РОЛЬ]: [название]

**Фаза:** [какая фаза]  
**Задача:** [какая задача]  
**Статус:** [что делаю сейчас]  

### Контекст
- Где я работаю: [файлы/компоненты]
- Какой процесс: [этапы]
- На каком шаге: [текущий шаг]

### Вопросы
Мне нужно уточнить:
- Вопрос 1?
- Вопрос 2?
- Вопрос 3?

### Как помочь
- [Вариант помощи 1]
- [Вариант помощи 2]
- [Вариант помощи 3]
```

## 🎓 Примеры обращений

### Researcher обращается

```
🔍 RESEARCHER: Code-Site (Текущая архитектура)

Фаза: Исследование (Research)  
Задача: Фаза 2 - Frontend специализация  
Статус: Исследую libs/ директорию  

Контекст:
- Где: platform/site/gj-ng-front/libs/
- Процесс: ПОИСК → ВАЛИДАЦИЯ → КОНФЛИКТЫ → ПОЛНОТА → ВЫВОД
- На шаге: ПОЛНОТА (4/5)

Вопросы:
- Какие libs критичны для специализации?
- Есть ли deprecated libs которые нужно избежать?
- Какие паттерны повторяются в компонентах?

Как помочь:
- Указать на важные libs
- Объяснить какие patterns использовать
- Подтвердить что я ничего не пропустил
```

### Analyst обращается

```
📊 ANALYST: Синтез Фазы 2

Фаза: Анализ (Analysis)  
Задача: Фаза 2 - Frontend специализация  
Статус: Разрешение конфликтов  

Контекст:
- Исследователи: 5 готовых выводов
- Процесс: КОНФЛИКТЫ → ПРОБЕЛЫ → ВАЛИДАЦИЯ → СТРУКТУРИРОВАНИЕ → ВЫВОД
- На шаге: КОНФЛИКТЫ (1/5)

Вопросы:
- Conf требует 6 скилов, Code предложил 7. Какой вариант?
- Scope: входит ли review-site-specialized в Фазу 2?
- Приоритет: UI первым или State?

Как помочь:
- Разрешить конфликт между Conf и Code
- Подтвердить scope
- Указать приоритет
```

### Developer обращается

```
💻 DEVELOPER: Создание 6 Frontend-скилов

Фаза: Разработка (Development)  
Задача: Фаза 2 - Frontend специализация  
Статус: Разработка develop-site-ui.md

- Процесс: ПОНИМАНИЕ → ПЛАН → КОД → SECURITY → ТЕСТЫ → КОММИТ → MR
- На шаге: КОД (3/7)

Вопросы:
- Требование "компоненты, стили, a11y" — как балансировать?
- Сколько примеров per topic?
- Нужно ли включать design-tokens примеры?

Как помочь:
- Уточнить требование по компонентам
- Показать примеры из других скилов
- Подтвердить что direction правильный
```

## ✨ Преимущества системы

✅ **Ясность:** Человек сразу понимает кто это и что он делает  
✅ **Контекст:** Агент указывает где он работает и на каком шаге  
✅ **Вопросы:** Конкретные вопросы вместо "помоги мне"  
✅ **Помощь:** Четкие варианты как помочь  
✅ **Трейсабилити:** Легко отследить выполнение задачи
