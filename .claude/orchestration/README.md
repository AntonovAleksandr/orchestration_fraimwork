## 🎯 Главная цель этого модуля

Орхестрация — это **управление** работой **6 ролей агентов** через 7 фаз выполнения задачи.

```
Требование → [Phase 1-7] → Merge
     ↓
Координатор управляет процессом через этот модуль
     ↓
Агенты выполняют работу согласно скилам
     ↓
Метрики и отчёты собираются автоматически
```

## 🚀 Быстрый старт (для координатора)

### 1. Запустить новую задачу

```bash
/task-research-and-analyze "JIRA_TICKET_ID"
```

Система автоматически:
- Запустит 5 исследователей параллельно (25 мин)
- Синтезирует постановку в аналитике (5 мин)
- Готово для разработчика

### 2. Проверить статус

```bash
/task-status
```

Увидишь:
```
Phase 1: Research 🔄 (60% готово)
  ├─ Conf: ✅
  ├─ Code-ENSI: ✅
  ├─ Code-OMS: 🔄
  ...
```

### 3. Разрешить [BLOCKER] вопрос

```bash
/blocker-resolve "blocker-001" --answer "Ответ от человека"
```

### 4. Собрать метрики

```bash
/task-metrics
```

Увидишь время, токены, качество, рекомендации

## 🔄 Циклический процесс ревью (КЛЮЧЕВО!)

**Этап ревью НЕ одноразовый**, а циклический:

```
ИТЕРАЦИЯ 1:
  Reviewer-1 + Reviewer-2 смотрят → находят замечания
  Developer фиксит → пушит обновлённый MR

ИТЕРАЦИЯ 2 (если нужна):
  Reviewer-1 + Reviewer-2 перепроверяют
  Если замечания resolved → Approved ✓
  Если новые замечания → ещё одна итерация

ЗАВЕРШЕНИЕ (когда ОБА Approved):
  Merge в main/release
```

**Команды для управления циклом:**
```bash
/review-start              # запустить ревью (iteration 1)
/review-status             # статус текущей итерации
/review-iteration 1        # показать детали итерации 1
/review-remind reviewer-1  # напомнить ревьюеру если затягивает
```

## 🔗 Связность: как скилы работают вместе

```
Исследователи (5)
    ↓ (выводы)
Аналитик (синтезирует)
    ↓ (постановка)
Разработчик (пишет код)
    ↓ (MR дифф)
Ревьюеры (2) ← проверяют параллельно
    ↓ (замечания)
Developer (фиксит) ← ЦИКЛ может повторяться!
    ↓
Координатор (merge + метрики)
```

**Каждый шаг явно загружает нужные скилы:**
- Исследователь: `research-*` + `shared-*`
- Аналитик: `analyze-*` + `shared-*`
- Разработчик: `develop-[platform]` + `shared-*`
- Ревьюер: `review-*` + `shared-*`
- Координатор: `coord-*` + `shared-*`

## ⚙️ Как не сломать существующие скилы

### Безопасность совместимости

✅ **ДЕЛАЕМ:** 
- Новые скилы в `.claude/skills/` и `.claude/orchestration/`
- Новые команды начинаются с `/task-`
- Существующие скилы Саши Закомирного работают как прежде

❌ **НЕ ДЕЛАЕМ:**
- Переимённовываем существующие файлы
- Меняем существующие скилы
- Конфликтуем с `orchestrate.sh` скриптами

### Почему это работает?

- `.claude/skills/` — новые скилы (30 файлов)
- `.claude/orchestration/` — новый модуль управления (этот файл + CONSOLE.md)
- Старые скилы остаются **в своих местах** и работают **как раньше**
- Новая система просто **добавляется параллельно**

## 🎯 7 фаз выполнения

```
Phase 0: Инициализация (2 мин)
    Координатор запускает систему

Phase 1: Research (25 мин, параллель)
    5 исследователей собирают факты одновременно

Phase 2: Analysis (5 мин)
    Аналитик синтезирует выводы в постановку

Phase 3: Development (30-60 мин)
    Разработчик пишет код по постановке

Phase 4-5: Review (20 мин, циклический!)
    Ревьюеры проверяют (может быть 2-3 итерации)
    Developer фиксит замечания параллельно

Phase 6-7: Merge + Metrics (5 мин)
    Координатор: merge, метрики, отчёт
```

**Итого:** 100 мин вместо 180+ (старая схема)

## 🆘 Troubleshooting

### Агент завис?

```bash
/task-intervene --phase 1 --action debug
# Посмотри лог, найди причину
/task-intervene --phase 1 --action restart --researcher "logs"
# Перезапусти
```

### [BLOCKER] вопрос не разрешается?

```bash
/blocker-ask --question "Уточни, что имеется в виду?"
# или пропусти
/blocker-skip "blocker-001" --note "Не критично для V1"
```

### Ревьювер затягивает?

```bash
/review-remind "reviewer-1"
# или давай заново проверить все замечания
```

## 💡 Ключевые инсайты

1. **Параллелизм** — 5 исследователей + 2 ревьювера работают одновременно
2. **Циклический ревью** — может быть 2-3 итерации, но Developer фиксит параллельно
3. **Узкий контекст** — каждый агент <20K токенов (не 150K как один координатор)
4. **Явная коммуникация** — между агентами через [BLOCKER], [NB], [MUST], [SHOULD] теги
5. **Автоматические метрики** — время, токены, качество собираются в конце
