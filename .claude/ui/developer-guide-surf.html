Developer Guide

Phase 2 Orchestration Framework — Getting started and best practices

Quick Start

1. Clone and Install

git clone https://github.com/your-org/orchestration_framework.git
cd orchestration_framework
pip install -r requirements.txt

2. Load Skills

claude-skills load --project gj-opsomn002
claude-skills list --layer project
claude-skills search debugging

3. Launch Framework

orchestrate.sh task --name my-task --phase 1
# In another terminal:
orchestrate.sh watch my-task
✓ You're ready! The framework is now running with Phase 2 hybrid orchestration.

Using Skills in Agents

Each agent prompt includes an "Available Skills" section that lists relevant skills. When working on a task:

  1. Check the agent's available skills section
  2. Load the project skills: claude-skills load --project your-project
  3. Search for relevant patterns: claude-skills search your-keyword
  4. Reference skills in your prompts

Implementation Guide

Worker Messaging Pattern

Phase 2 uses atomic file-based messaging between workers:

import os
import fcntl
import json
from pathlib import Path

def send_message(worker_id, phase, status):
    msg_file = Path(f".tasks/{worker_id}/phase-{phase}.msg")
    msg_file.parent.mkdir(parents=True, exist_ok=True)

    with open(msg_file, 'w') as f:
        fcntl.flock(f, fcntl.LOCK_EX)
        json.dump({"status": status}, f)
        fcntl.flock(f, fcntl.LOCK_UN)

Phase Coordination

Phases run in parallel with data-driven validation:

Phase 1: Research     → Phase 2: Analysis     → Phase 3: Synthesis
         ↓                        ↓                          ↓
      (1 hour)               (parallel 2h)              (1.5 hours)

Validation gates between phases ensure data quality.

Risk Management

6 identified risks in Phase 2 orchestration:

  1. Race conditions: Mitigated by atomic writes
  2. Timeout cascades: Independent phase timeouts
  3. Resource exhaustion: Worker pool limits
  4. Validation gaps: Data-driven gates
  5. IDE incompatibility: Adapter pattern
  6. Skills discovery: CLI + web UI

Frequently Asked Questions

What is the orchestration framework?
A hybrid multi-agent coordination system that combines async worker messaging with parallel phase execution. It enables complex workflows across multiple agents with data validation gates between phases.
How do I run my first orchestration task?
orchestrate.sh task --name my-task --phase 1 starts a new task. Run orchestrate.sh watch my-task in another terminal to monitor progress.
What are the 3 skill layers?
Project: GJ-specific (gj-reviewer, TDD, debugging)
Stack: Platform-specific (develop-site-ui, develop-oms-java)
Generic: Universal patterns (pattern-development-flow, pattern-review-standard)
How do I discover available skills?
Use the CLI: claude-skills list
Use the web dashboard: Skills Dashboard
Check your agent's "Available Skills" section in its prompt
What if a phase times out?
Each phase has an independent timeout (default 2 hours). If a phase times out, check the logs with orchestrate.sh logs task-name phase-N and retry the phase independently.
Can I use the framework on my own project?
Yes! The framework is fully open-source and sanitized. Clone it from GitHub and follow PHASE2-QUICKSTART.md. It's designed to be reusable across projects.
Is Phase 2 production-ready?
Yes, Phase 2 is at 10/10 status and ready for production. All P0 blockers are fixed. Phase 3 (enterprise features) is planned for Q4 2026.
How does data validation between phases work?
Each phase gate checks validation rules before advancing. If validation fails, the phase can retry or escalate. This prevents bad data from propagating downstream.
What IDEs are supported?
Currently: Claude Code (native) and Cursor (via symlink adapter). VSCode and JetBrains adapters are planned for Phase 3.
Can I contribute to the framework?
Absolutely! The repository is open to contributions. Please follow the Phase 2 patterns documented here and open PRs with clear descriptions.
