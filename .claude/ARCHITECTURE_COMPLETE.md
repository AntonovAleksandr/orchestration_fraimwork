## 🎯 Архитектура

### 6 ролей агентов

| Роль | Контекст | Скилы | Время |
|------|----------|-------|-------|
| **Координатор** | 10K | coord-* + shared-* | всё время |
| **Исследователь (5)** | 8-15K каждый | research-* + shared-* | 5 мин каждый |
| **Аналитик** | 8K | analyze-* + shared-* | 5 мин |
| **Разработчик** | 20K | develop-[platform] + shared-* | 30-60 мин |
| **Reviewer-1** | 15K | review-business-* + shared-* | 20 мин (× циклы) |
| **Reviewer-2** | 15K | review-security-* + shared-* | 20 мин (× циклы) |

### 7 фаз выполнения

```
Phase 0 (2 мин)    → Инициализация (Координатор)
Phase 1 (25 мин)   → Research (5 исследователей ПАРАЛЛЕЛЬНО)
Phase 2 (5 мин)    → Analysis (Аналитик)
Phase 3 (30-60 мин)→ Development (Разработчик)
Phase 4-5 (20 мин) → Review (2 ревьювера ПАРАЛЛЕЛЬНО, ЦИКЛИЧЕСКИЙ)
Phase 6-7 (5 мин)  → Merge + Metrics (Координатор)
───────────────────
ИТОГО: 100 мин (вместо 180+)
```

### 30 скилов разделены на категории

- **[RESEARCH]** — 6 скилов (исследователи)
- **[ANALYSIS]** — 3 скилла (аналитик)
- **[DEVELOPMENT]** — 7 скилов (разработчики 7 платформ)
- **[REVIEW]** — 3 скилла (2 ревьювера + чеклисты)
- **[COORDINATION]** — 4 скилла (координатор)
- **[SHARED]** — 7 скилов (все агенты)

## ✨ Ключевые особенности

### 1. Циклический ревью (ВАЖНО!)

```
❌ Неправильно: один проход → merge
✅ Правильно: может быть 2-3 итерации
  - Iteration 1: замечания → Developer фиксит
  - Iteration 2: перепроверка → если OK → merge
```

### 2. Параллелизм

- 5 исследователей одновременно
- 2 ревьювера одновременно
- Developer пишет параллельно с ревью

### 3. Явная коммуникация

- `[BLOCKER]` = критичное (блокирует)
- `[NB]` = некритичное (параллельно)
- `[MUST]` = обязательно фиксить
- `[SHOULD]` = рекомендация

### 4. Автоматические метрики

```
/task-metrics → время, токены, качество, рекомендации
```

### 5. Безопасность совместимости

- Скилы Саши Закомирного работают как прежде
- Новая система добавляется параллельно
- Не конфликтует с CLAUDE.md правилами
