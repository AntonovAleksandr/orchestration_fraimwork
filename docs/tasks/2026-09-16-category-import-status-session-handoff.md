# Передача доработки статуса импорта в отдельные сессии

Дата: 2026-09-16. Цепочка: **C → ревью и публикация pimclient → D → ревью intgateway**.

## Сессия C: Go-клиент PIM

Скопировать в новую сессию:

```text
В workspace GJ-Ecommerce выполни ТЗ docs/superpowers/plans/2026-09-16-pimclient-import-status-spec.md целиком.
Рабочий репозиторий platform-new/clients/pim. Требуется GetProductImport, generated DTO, typed errors и тесты. ТЗ самодостаточное; прочитай его и применимые инструкции до изменений.
Другие репозитории не менять. Не коммитить, не пушить, не выпускать версию, не обращаться к реальному PIM. После реализации представь отчёт по ТЗ и остановись для ревью.
```

[Открыть ТЗ C](../superpowers/plans/2026-09-16-pimclient-import-status-spec.md).

Владелец проводит ревью и отдельным поручением выпускает клиент. Исполнителю D передаётся реальный опубликованный тег с GetProductImport; v0.2.0 не подходит.

## Сессия D: GET в intgateway

Запускать после публикации клиента. В сообщение добавить фактический одобренный тег.

```text
В workspace GJ-Ecommerce выполни ТЗ docs/superpowers/plans/2026-09-16-intgateway-import-status-spec.md целиком.
Рабочий репозиторий platform-new/intgateway. Требуется GET /api/v1/catalog/category-position-imports/{import_id} для UI AutoMerch.
Начни с текущего working tree с уже реализованным POST: изменения POST могут быть незакоммичены и включать untracked файлы. Не создавай чистую копию от старого HEAD, не откатывай чужую работу.
Подключи переданный владельцем опубликованный тег pimclient с GetProductImport. Если тег не указан или недоступен, сообщи об этой зависимости; не придумывай тег и не подменяй клиент local replace.
Прочитай ТЗ и применимые инструкции. PIM, клиент и AutoMerch не менять. Не коммитить, не пушить, не деплоить, не обращаться к реальному PIM. После реализации представь отчёт по ТЗ и остановись для ревью.
```

[Открыть ТЗ D](../superpowers/plans/2026-09-16-intgateway-import-status-spec.md).

Для полного выполнения и сдачи сессии последовательные. Подготовка домена/контракта D с fake port возможна параллельно C, но не заменяет подключение опубликованного клиента и интеграционные тесты.
