# Stage 03 — Ozon

**Дата:** 2026-07-23  
**Статус:** complete-for-current-pass  
**Уровень покрытия:** Jira + Confluence + точечная сверка локального кода 1С

## 0. Scope и правила интерпретации

В этом документе рассматривается именно продажа Gloria Jeans на маркетплейсе Ozon:

- коммерческая модель и исполнение заказов;
- карточки, идентификаторы товаров, цены и остатки;
- поставки, приёмка, маркировка и ЭДО;
- заказы, отмены, продажи, возвраты и финансовая сверка;
- роль `OZON Connector`, WebApi и 1С;
- текущие роли и свежие задачи.

Не следует смешивать этот контур с использованием **Ozon Доставки как транспортной компании** для собственных e-commerce-заказов GJ.

Шкала уверенности:

- **confirmed** — есть свежая завершённая/активная Jira-задача, согласованный документ или прямое подтверждение в коде;
- **high-confidence** — несколько согласующихся источников, но нет runtime-проверки;
- **proxy** — найдено описание, интерфейс или кодовая возможность, но использование в текущем процессе не доказано;
- **hypothesis** — рабочее предположение для дальнейшей проверки;
- **unknown** — доступные источники не позволяют сделать вывод.

Confluence описывает намерение или состояние на дату страницы, но не доказывает текущую промышленную эксплуатацию. Особенно это относится к страницам с `TBD`, статусом «Черновик» и следами копирования из других маркетплейсов.

## 1. Краткий итог

1. **Рабочий и актуально развиваемый контур Ozon — FBO.** В 2026 году WebApi переведён с `v2/posting/fbo/list` на `v3/posting/fbo/list`; задача разработки закрыта, тестирование завершено. Отдельная инициатива по DBS/FBS отменена. Это подтверждает FBO, но не является доказательством отсутствия любых FBS-операций во всех системах (`OPSMPC-1074`, `OPSMPC-1078`, `OPSMPC-190`). **Confidence: confirmed.**
2. **Операционное ядро обмена — не ENSI/OMS, а связка Ozon Seller API → GJ WebApi/API GW → обработки 1С Ecomm.** `ОбменOZON` создаёт и корректирует документы 1С по заказам, продажам, возвратам и отменам; используются дополнительные обработки `СверкаРеализацийOzon`, `КорректировкаOZON` и ручная загрузка расхождений (`page_id=44264974`, v87, updated 2025-08-13; `OPSMPC-1102`, `OPSMPC-1103`). **Confidence: high-confidence**, без runtime-проверки.
3. **Приёмка и финальная финансовая сверка остаются полуручными.** Автоматическую загрузку результата приёмки через старый API отключили ещё в 2023 году как некорректную; действующий документ описывает загрузку Excel-файла из ЛК и создание списаний/оприходований. Ежемесячная сверка выполняется по официальному позаказному отчёту с последующей ручной дозагрузкой и корректировкой документов (`page_id=44264974`; `page_id=165398439`, v7, updated 2026-07-07). **Confidence: high-confidence.**
4. **Старую автоматизацию через ENSI/Ozon Connector подтвердить как промышленный as-is не удалось.** Архитектурная схема существует, но ADR помечен «Черновик», содержит `TBD` и следы копирования Kaspi; согласовательные задачи `ONPLAN-169..172` отменены, отложены или не завершены. При этом для **витринных цен** найден другой, более свежий контур: Price Formation → ApiGW → DataBird → Ozon. Он подробно описан, а задача внедрения Ozon-цен закрыта (`page_id=149765159`, v6; `OPSMPC-620`). **Confidence: high-confidence documentary для DataBird-цепочки; runtime/SLA не проверены.**
5. **DataBird связан и с наполнением Ozon-карточек**, но доступная Ozon-задача содержит только название «Загрузка атрибутов товаров, поднимающих рейтинг» и статус «В работе». Контракт, частота, перечень атрибутов и границы ручной работы из этой задачи не восстанавливаются (`OPSMPC-655`). Документ по ценам показывает, что импорты PF могут создавать отсутствующие товары в каталоге DataBird, но не доказывает полноценное создание и ведение контентной карточки Ozon. **Confidence: proxy.**
6. На 2026-07-21 шёл переход финансового обмена на новый API начислений Ozon: WebApi-метод закрыт, тест завершён, версия `ОбменOZON` была в статусе «Перенос на прод», а отдельная задача по утечкам памяти оставалась в разработке (`OPSMPC-1102`, `OPSMPC-1113`, `OPSMPC-1103`, `OPSMPC-1114`). **Считать миграцию полностью принятой в production нельзя.**

## 3. Карточки, DataBird, идентификаторы, цены и остатки

### 3.1 Исторический процесс карточек

Регламент 2021 года описывает ручной процесс:

1. операционный менеджер формирует список новых моделей;
2. внешняя обработка 1С создаёт спецификацию;
3. поля спецификации и ссылки на фотографии вручную корректируются;
4. файл загружается в ЛК Ozon для создания карточек;
5. ошибки по атрибутам и ценам разбираются вручную.

Источник: `page_id=89982522`, v3, updated 2025-03-11, но содержательная версия процесса датирована 2021 годом.  
**Статус:** исторический; использовать как текущую инструкцию нельзя.  
**Confidence:** confirmed historical.

### 3.2 Историческая проектная автоматизация через ENSI/Ozon Connector

`page_id=74176746`, v29, updated 2023-10-16, описывает план автоматического создания карточек:

```text
Catalog ENSI → Ozon Connector → Ozon Seller API
```

Предполагались сравнение уже созданных товаров, проверка лимитов Ozon, создание товара через API и сохранение статуса транзакции. Документ заполнен частично и содержит пустые разделы.

`page_id=82010279`, v28, updated 2024-04-23, описывает более общую архитектуру:

- WebApi Connector забирает обычные и акционные цены из Price Formation;
- ENSI хранит карточки, marketplace-атрибуты, маппинг и external ID;
- отдельный connector для каждого маркетплейса получает карточки/цены из ENSI и передаёт их в API маркетплейса;
- статусы и ошибки загрузки возвращаются в ENSI;
- должны поддерживаться расписание, ручной запуск, batch-обработка, логи и уведомления.

Однако:

- ADR имеет статус **«Черновик»**;
- в интерфейсах Ozon встречаются ошибочные ссылки на `Kaspi Connector` и темы писем с Kaspi (`page_id=89984340`, v13; `page_id=89984382`, v17; `page_id=82012781`, v27);
- в страницах остаются `TBD`;
- связанные задачи согласования `ONPLAN-169` отменена, `ONPLAN-170` отложена, `ONPLAN-171` осталась на согласовании, `ONPLAN-172` — «Комментарии получены»; последние изменения относятся к 2023–2024 годам;
- в GitLab найден общий проект `greensight/gj/catalog/mp-connector` (`project_id=820`), но получить его метаданные и содержимое в этом проходе не удалось из-за таймаута Buddy. Отдельный проект по запросу `ozon` не найден.

**Verdict:** это историческая проектная архитектура, а не подтверждённый as-is. Нельзя утверждать, что текущие карточки или цены Ozon идут из ENSI через Ozon Connector. Для цен найден отдельный более свежий DataBird-контур, описанный ниже.  
**Confidence: confirmed draft / unknown runtime.**

### 3.3 DataBird в Ozon

Для цен найден отдельный подробный ADR `page_id=149765159`, v6, «Databird — Загрузка цен в Маркетплейсы». Хотя сама страница имеет статус **«Черновик»**, она описывает конкретные импорты, экспорты, атрибуты и формулы, а Jira `OPSMPC-620` «Внедрение DataBird. OZON — Цены» имеет статус **305 — Работа завершена**, updated 2025-05-12.

Документированная цепочка:

```text
Price Formation → ApiGW → импорты DataBird → каталог DataBird
Ozon Seller API → импорт текущих цен в DataBird
DataBird сравнивает PF-цену с Ozon-ценой → при расхождении экспортирует обновление в Ozon
```

По ADR операции выполняются ежедневно по расписанию. Для Ozon описаны:

- обычная, акционная и первая/зачёркнутая цены из Price Formation;
- приоритеты ручных Excel-корректировок над PF;
- минимальные пороги и преобразование первой цены под ограничения Ozon;
- исключения `black_list` и `bl_OZON`;
- фильтр, отправляющий только позиции, у которых рассчитанная цена отличается от цены, загруженной из Ozon;
- ручная корректировка каталога DataBird и необходимость отдельно проверять ошибки конкретных SKU;
- эксплуатационный риск: после изменения импорта/экспорта расписание может переключиться на ручной режим.

**Verdict по ценам:** документально подтверждён реализованный процесс PF → ApiGW → DataBird → Ozon, а не старый ENSI/Ozon Connector. Статус задачи внедрения усиливает вывод, но без логов, последнего запуска или runtime-конфигурации нельзя утверждать, что процесс работает сейчас без сбоев и именно по указанному ежедневному расписанию.  
**Confidence: high-confidence documentary; unknown current runtime/SLA.**

`OPSMPC-655`:

- summary: «OZON. Databird. Загрузка атрибутов товаров, поднимающих рейтинг»;
- тип: Action Item;
- статус: **155 — В работе**;
- assignee/reporter: Павел Габдулин;

Из задачи можно подтвердить только наличие продолжающейся активности по загрузке в Ozon атрибутов, влияющих на рейтинг карточек. ADR цен дополнительно говорит, что PF-импорты могут создать отсутствующую товарную запись в каталоге DataBird, а импорты с `NEW_SKU` создают товары без цен. Это не доказывает, что DataBird создаёт полноценную карточку в Ozon или является master для контента. Не подтверждены:

- является ли DataBird мастер-системой или инструментом массового редактирования;
- откуда DataBird получает контент;
- какие атрибуты передаются;
- создаёт ли он карточки или только обогащает существующие;
- кто подтверждает изменения и разбирает ошибки;
- есть ли автоматическое расписание и обратная синхронизация именно для контентных атрибутов.

**Confidence по атрибутам карточки: proxy.** Детальный процесс должен быть согласован со Stage 02 — DataBird.

### 3.4 Идентификаторы Ozon

Проектные интерфейсы предполагают:

1. получить из ENSI SKU без `externalId`;
2. запросить Ozon `/v2/product/list` по EAN/`offer_id`;
3. записать `product_id` как `externalId` обратно в каталог;
4. использовать его при обновлении цены.

Источники: `page_id=89984340`, v13; `page_id=89984382`, v17; `page_id=89984397`, v17.

Свежая Jira:

- `OPSMPC-868` «Доступность ИдентификаторовМП для 1С и других систем» — **Работа завершена**, updated 2026-05-13;
- дочерняя/специализированная Ozon-задача `OPSMPC-871` — **Отмена**, updated 2025-10-10.

**Verdict:** общая доступность marketplace-ID была реализована, но отдельный механизм/потребитель Ozon из доступных задач не восстанавливается. Нельзя автоматически приравнивать завершение `OPSMPC-868` к запуску старого Ozon Connector.  
**Confidence: high-confidence для общей функции; unknown для Ozon Connector.**

### 3.5 Витринные цены

Для старого ENSI/Ozon Connector проектный контракт описывает:

- выбор обновлённых цен из offer ENSI;
- фильтрацию товаров без `externalId`;
- передачу партиями до 1000 товаров в Ozon `/v1/product/import/prices`;
- возврат статуса `Ok`/ошибки в ENSI.

Источники: `page_id=89984405`, v13; `page_id=82012781`, v27; оба относятся к проектной ветке 2023–2024 годов и не являются доказательством эксплуатации.

Свежие задачи `OPSMPC-959..962` подтверждают изменение расчётной цены **в документах заказов 1С** при изменении договорной комиссии до 34% с 2026-02-01. Они не подтверждают механизм выгрузки витринной цены на Ozon.

Более свежий DataBird ADR описывает уже другой процесс: обычные и акционные цены ежедневно забираются из Price Formation через ApiGW, текущие цены отдельно загружаются из Ozon, после сравнения и преобразования DataBird отправляет расхождения в Ozon. Для Ozon приведены конкретные атрибуты, фильтры и формулы (`page_id=149765159`, v6). Задача внедрения `OPSMPC-620` закрыта 2025-05-12.

**Verdict:** документированный source для продажных цен — Price Formation, транспорт — ApiGW → DataBird → Ozon. Старый ENSI/Ozon Connector не следует смешивать с этой цепочкой. Текущие расписания, последний успешный запуск, SLA, ошибки и фактическая runtime-конфигурация не проверены.  
**Confidence: high-confidence documentary; unknown current runtime/SLA.**

## 4. Поставки, маркировка, ЭДО и приёмка

### 4.1 Историческая поставка FBO

`page_id=89982522` описывает цепочку:

1. планирование ассортимента и объёма;
2. создание заявок на отбор и батча в WMS;
3. создание поставки и слота в ЛК Ozon;
4. привязка перемещений 1С к номеру поставки;
5. формирование УПД и паллетных ШК;
6. доставка на склад Ozon;
7. паллетная и поштучная приёмка;
8. фиксация расхождений, брака и излишков;
9. отражение приёмки и корректировок в 1С.

Это наиболее полный источник по end-to-end процессу, но его роли, ограничения и инструменты относятся в основном к 2021 году. Например, лимит в 7000 SKU и конкретные склады нельзя считать актуальными без проверки.

### 4.2 Подтверждённый контур маркировки из Новосибирска

`page_id=108065446`, v118, updated 2024-07-23, и согласование `DEVLBL001-4564` (**395 — Согласовано**, 2024-06-14) описывают FBO-отгрузку маркированного товара:

1. `GJMarkUpdate` по расписанию забирает документы и марки из 1С 8 ЛЦ НСК;
2. проверяет данные и передаёт УПД-1 в `WebGJISMP`;
3. `WebGJISMP` отправляет УПД-1 через СБИС/ЦРПТ для движения между юрлицами GJ;
4. затем аналогично отправляется УПД-2 по агентской схеме с АО на Ozon;
5. статусы возвращаются через `WebGJISMP`/`GJMarkUpdate` в 1С;
6. Ozon выводит марки из оборота при продаже по чеку.

**Confidence: confirmed design and approval; runtime not checked.**

## 5. Заказы, продажи, отмены и возвраты

### 5.1 Текущая интеграционная цепочка

```text
Ozon Seller API (FBO)
        ↓
GJ WebApi / API GW
        ↓
ОбменOZON в 1С Ecomm
        ↓
РК+ / РК- / РРН / ПН
```

## 6. Финансы и сверка

## 10. Риски, которые нельзя потерять

1. **Легаси 1С — критическая точка контура.** Свежие изменения по API Ozon требуют правок внешних обработок, файловых каталогов и ручных сверок; задача по утечке памяти уже показывает эксплуатационный предел (`OPSMPC-1114`).
2. **API-ответ не равен финансовой истине.** Для закрытия периода используется официальный отчёт ЛК; текущая формула и состав отчёта меняются, что создаёт риск неверных РРН/ПН и выручки (`165398439`, `OPSMPC-1115/1116`).
3. **Приёмка и маркировка имеют незакрытый automation-gap.** Проект XML УПД-2 согласован, но реализация приостановлена; остаётся зависимость от ручных файлов и осторожного изменения документов закрытого периода.
4. **Карточки не имеют подтверждённого end-to-end владельца и source of truth.** Для цен DataBird-цепочка документирована, но её актуальный runtime и владелец эксплуатации не проверены; наличие старого ENSI-дизайна не является доказательством параллельной промышленной цепочки.
5. **Документация содержит секреты в открытом виде.** В `page_id=40442552`, `page_id=165405930`, `page_id=149779622` и `OPSMPC-1102` найдены неплейсхолдерные значения Ozon API credential. Они намеренно не перенесены сюда. Требуются отзыв/ротация и очистка страниц/истории. **Confidence: confirmed security finding.**
6. **Копипаст в интеграционных документах.** Страницы Ozon Connector упоминают Kaspi Connector и Kaspi в почтовых уведомлениях. Это снижает доверие ко всей ветке как к исполняемому контракту.
