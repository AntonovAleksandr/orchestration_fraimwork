# Stage 01 — общий контур направления маркетплейсов

**Дата среза:** 2026-07-23  
**Статус:** complete-for-current-pass  
**Уровень покрытия:** Jira/Confluence, без runtime-проверки

## 0. Scope

Организационная и системная карта направления: площадки, процессы и основные
границы между контентом, ценами, поставками, заказами и финансами.

## 1. Резюме

Направление маркетплейсов — самостоятельный операционно-интеграционный контур,
а не часть только интернет-магазина GJ. Его наиболее заметные технические центры:

1. **DataBird + Price Formation** — автоматизация цен; товарные карточки через
   DataBird находятся в отдельном, незавершённом потоке.
2. **PIM ENSI / PLM / 1С** — источники и подготовка товарных данных и контента.
3. **1С7 Ecom / 1С7 WB, WebApi, отдельные обмены и обработки** — поставки,
   продажи, возвраты, приёмка, УПД и сверки.
4. **Личные кабинеты и API площадок** — фактическая публикация, данные о
   поставках, продажах, остатках и финансовых отчётах.
5. **DWH/отчётные БД** — отчёты по карточкам, остаткам, продажам и сверкам.

Это разделение подтверждается разными наборами источников и свежими задачами
OPSMPC. DataBird нельзя считать универсальной шиной всех процессов МП.

## 2. Подтверждено / высокая уверенность

### 2.1. У направления есть отдельный проект и постоянная операционная работа

- Jira-проект `OPSMPC` содержит задачи по Ozon, WB, Яндекс Маркет, Lamoda,
  Kaspi и общим обработкам маркетплейсов.
- За период 2026-07-01—2026-07-23 найдено 38 обновлённых задач. Среди них:
  `OPSMPC-446` «Marketplaces. Инциденты» и `OPSMPC-311`
  «Marketplaces. Документация» — обе в работе; `OPSMPC-200` —
  действующая координация разработки.
- Актуальный поток июля 2026 особенно насыщен задачами Ozon по продажам,
  возвратным корректировкам и финансовой сверке, а также заменой недельного
  финансового API WB (`OPSMPC-1107`).

**Уверенность:** high. Jira подтверждает живую работу, но не полный бизнес-периметр.

### 2.2. Системный контур шире e-commerce платформы

Страница онбординга `page_id=89985772`, версия 17, обновлена 2025-05-23,
называет рабочими системами 1С7 Ecom, 1С7 WB, WebApi, DWH и Kibana.
Роли направления включают руководителя группы операций и менеджеров по работе с МП.

**Уверенность:** confirmed для описанного онбордингом контура; актуальность
персонального состава отдельно не проверялась.

### 2.3. Площадки встречаются в источниках в разных наборах

- Историческая матрица API `page_id=81986146` (2024-04-27) описывает WB,
  Ozon, Lamoda, СберМегаМаркет и Kaspi.
- DataBird-ADR `page_id=149765159` (2025-08-05) описывает цены WB, Ozon и
  Яндекс Маркета.
- Свежие задачи Jira 2026 года подтверждают активные изменения Ozon и WB.
- По Яндекс Маркет, Lamoda и Kaspi есть завершённые/исторические задачи, но
  текущий объём продаж и операционная активность этим исследованием не подтверждены.

**Вывод:** нельзя превращать найденный перечень в список «активных сейчас»
площадок без данных бизнеса или свежей операционной выгрузки.

## 3. Карта процессов

| Процесс | Основные системы по источникам | Текущее состояние |
|---|---|---|
| Карточки и контент | фото/сеть → PIM ENSI; PLM/1С → PIM; далее ЛК/фиды/DataBird | Ozon/WB через DataBird в реализации; текущий AS-IS не подтверждён целиком |
| Цены | Price Formation → ApiGW → DataBird → API МП | WB/Ozon/Яндекс внедрение завершено по Jira; live runtime не проверен |
| Остатки | 1С, ЛК/API МП, отчётные сервисы/БД | есть отдельные сверки WB/Ozon; единый мастер не установлен |
| Поставки и приёмка | 1С, обработки Обмен*, УПДМаркетплейс, API/ЛК МП, ЭДО | отдельные процессы по площадкам; часть ручных шагов исторически присутствует |
| Маркировка/УПД | 1С8 ЛЦ, GJMarkUpdate, СБИС/ЦРПТ, МП | подтверждён отдельный от DataBird контур |
| Продажи/возвраты | API МП → WebApi/агенты → 1С/отчётные БД | живой контур; в 2026 активно менялся для Ozon/WB |
| Финансовая сверка | отчёты/API МП → обработки сверки в 1С/БД | живой и регулярно дорабатываемый процесс |

## 4. Исторические решения, которые нельзя считать текущей архитектурой

- `page_id=82001707` (черновик, обновлён 2023-08-09) предлагал отдельный
  connector на каждый маркетплейс и раздельные процессы карточек, цен и остатков.
- `page_id=82010279` (черновик, обновлён 2024-04-23) подробно проектировал
  собственные МП Connector + Catalog ENSI.
- Более свежие источники 2025–2026 показывают, что для цен выбран DataBird,
  а карточки Ozon/WB всё ещё проходят отдельную реализацию.

Эти ADR полезны как история требований и объяснение границ процессов, но не как
доказательство production-архитектуры.

## 5. Противоречия и ограничения

- Пустые страницы `Operations Маркетплейсы Home` (`97898561`) и
  `Домен. Маркетплейсы` (`130123316`) не дают канонической карты домена.
- Страница потоков `130122894` хранит содержательную схему в изображении,
  которое Buddy не извлёк; текстовая часть недостаточна.
- Статус Jira «завершено/закрыто» подтверждает завершение работы, но не
  production-запуск и не отсутствие последующих ручных операций.
- В Confluence одновременно существуют старые AS-IS, черновики TO-BE и свежие
  технические спецификации. Их нельзя смешивать без дат и статусов.

## 6. Неизвестно

- Канонический владелец бизнес-направления и актуальная RACI.
- Полный список площадок, на которых идут продажи на дату среза.
- Объёмы по FBO/FBS/DBS и фактическое использование моделей по площадкам.
- Какие операции контент-команды сегодня остались ручными после внедрения DataBird.
- Где находится единый источник истины по остаткам и продажам для управления МП.
