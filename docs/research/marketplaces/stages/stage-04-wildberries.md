# Stage 04 — Wildberries

**Дата:** 2026-07-23  
**Статус:** complete-for-current-pass  
**Уровень покрытия:** substantial по документам Jira/Confluence, partial по фактическому production-as-is

## 0. Scope

В stage входят:

- товарные карточки и контент WB;
- цены и DataBird;
- остатки и замеры склада WB;
- заказы, продажи, отмены и возвраты;
- поставки, приемка, маркировка, УПД и ЭДО;
- финансовые отчеты и сверки;
- историческая проработка FBO/FBS/DBS и QR-поставок;
- найденные владельцы и исполнители.

Не входят:

- live-проверка личного кабинета WB, DataBird, 1С, БД, job и production-логов;
- подтверждение текущих объемов продаж, количества карточек и складов;
- юридическая экспертиза договорной модели с WB;
- описание других маркетплейсов, кроме пересечений в общих инструментах.

### Термины и ограничения интерпретации

- В старых документах GJ используется терминология `FBO`/`FBS`, в новых API-страницах WB встречаются «Склад WB», «Склад продавца», поставки FBW и виртуальные поставки. Эти обозначения не считаются автоматически эквивалентными без подтверждения владельца процесса.
- Закрытая задача означает, что работа прошла Jira workflow, но сама по себе не доказывает успешную эксплуатацию в production.
- Страница с названием `[NEW]`, `финальная реализация` или `актуально` считается спецификацией, но не runtime-доказательством.
- `confirmed` — источник прямо утверждает факт; `high-confidence` — несколько независимых источников согласуются; `proxy` — проектная документация или статус задачи без live-подтверждения; `unknown` — подтверждения нет.

### Оценка свежести

- **fresh** — источник обновлен в 2026 году;
- **recent** — источник обновлен в 2025 году;
- **historical** — источник 2024 года или старше;
- для Jira дополнительно указано состояние на 2026-07-23.

## 2. Исторические процессы

### 2.1. Базовый процесс поставки WB

Регламент 2020–2023 годов описывал преимущественно поставку на склад WB:

1. Планирование формировало список моделей, а операционный менеджер проверял контент, фото и цену.
2. Логисты создавали заявки в 1С, WMS группировала их в батчи, после отбора появлялись перемещения.
3. Заказ и спецификация передавались операционному менеджеру.
4. Новые карточки создавались через загрузку спецификации в ЛК WB; заказ загружался отдельно.
5. После подтверждения назначалась дата поставки, номер/ШК передавались логистам и записывались в 1С.
6. Формировались ТрН/Торг-13 и УПД, затем товар принимался WB.

Evidence: page_id `27891317`, page_id `20974732`. Это **historical**, а не подтвержденный текущий процесс.

### 2.2. FBO/FBS/DBS

- В сравнительном исследовании 2024 года для WB указаны используемые бизнес-модели `FBO, FBS` (page_id `81986146`, updated 2024-04-27).
- Jira `OPS-10382` (`Исследование возможности FBS и DBS на Wildberries`) завершена в феврале 2024 года, но содержит только постановку «понять, можем ли работать»; результатов, решения и критериев запуска в issue нет.
- `OPSLOG-754` (`FBS_оценка`) завершена в июле 2024 года, но не содержит описания или комментариев.
- В свежем проекте `OPSMPC` нет отдельной завершенной цепочки WB FBS/DBS. Поиск `FBS`/`DBS` дает преимущественно общие coordination items и задачи других маркетплейсов.
- Свежий контракт заказов WB содержит поле `warehouseType` со значениями «Склад WB»/«Склад продавца» (page_id `165397303`), но это схема API, а не доказательство, что GJ реально получает заказы обоих типов.

**Вердикт:** историческая проработка FBS/DBS подтверждена. Текущую эксплуатацию WB FBS или DBS подтвердить нельзя. Документированные поставки на склады WB и складские остатки дают high-confidence для warehouse-fulfillment контура, но название конкретной бизнес-модели следует подтвердить в ЛК/у владельца.

### 2.3. QR-поставки

`OPSMPC-183` по новой схеме QR-поставок находится в статусе `Приостановлена` с июня 2024 года. В комментариях: были сформулированы вопросы WB, затем ожидалась тестовая поставка и возобновление поставок. Подтверждения запуска нет.

### 2.4. Эволюция после 2024 года

- 2025: внедрение цен через DataBird, инструменты сверки остатков, восстановление приемки и виртуальных поставок, развитие УПД по акту приемки.
- 2026: новые контракты orders/sales/weekly, сервис замеров WB, статус ЭДО в сверке поставок, доработки полноты `srid`.
- Товарные карточки через DataBird на март 2026 года остаются в реализации.

```text
  ├─ Feed-WB API → 1С7 ЛЦ НШ → ручное обновление каталога/ЛК WB
  │    confirmed contract, фактическая частота неизвестна
  └─ товарный фид → DataBird → WB Content API

                              documentary high-confidence, runtime не проверен
```

### 3.2. Заказы, продажи и финансы

```text
WB Orders/Sales API
  → API GW (WebApi)
  → 1С7 WB / ОбменWB
  → РК+, РК-, РРН, ПН
  → бухгалтерские и операционные выгрузки

WB weekly financial API
  → import_weekly_WB job / SSIS
  → wb_weekly
  → финансовая отчетность/сверки
```

Эта ветка имеет самые свежие признаки сопровождения (`OPSMPC-1107`, `OPSMPC-1051`).

### 3.3. Остатки и поставки

```text
WB warehouse reports
  → BI/служебные БД
  → отчеты остатков и поставок

1С/WMS склада GJ
  → батчи/короба/паллеты/перемещения
  → номер поставки/ШК WB
  → поставка и приемка WB
  → ОбменWB / УПДМаркетплейс
  → списание/оприходование и сверка
```

Для маркированного товара дополнительно документирован контур:

```text
1С8 → GJMarkUpdate → WebGJISMP → СБИС → ЦРПТ
                                      └→ УПД/ЭДО для WB
```

## 4. Противоречия и слабые места источников

1. **Карточки: manual AS IS против DataBird to-be.** Draft page_id `149768494` описывает ручную XLS-загрузку; `OPSMPC-862/863` показывают незавершенную автоматизацию. Свежий Feed-WB page_id `165408341` все еще называется API для ручного обновления.
2. **Цены: Jira closed, ADR draft.** `OPSMPC-550` завершена, но page_id `149765159` имеет статус `Черновик`. Нужны фактические DataBird run history и выборочная сверка WB.
3. **FBS/DBS: исследование без результата.** `OPS-10382` и `OPSLOG-754` подтверждают работу над вопросом, но не ее вывод. Page_id `81986146` не заменяет подтверждение активной схемы.
4. **Старые регламенты содержат устаревшие роли, адреса, склады и ручные шаги.** Page_id `27891317` и `20974732` нельзя использовать как текущий runbook.
5. **Новые страницы описывают интерфейсы, но не дают runtime evidence.** В частности, page_id `165397303`, `165397510`, `165382074`, `130128672`, `165411281`.
6. **В описании `OPSMPC-1107` размещен секретоподобный bearer token.** Значение намеренно не перенесено. Необходимо проверить, активен ли он, и при необходимости отозвать/перевыпустить.
7. **Page_id `149773843` содержит credential-like параметры в API URL.** Значения намеренно не перенесены. Требуется security hygiene review и ротация, если секреты еще действуют.
8. **Отчет по карточкам и ХД не завершены.** `OPSMPC-472` с декабря 2024 года в `Ожидание разработки`, поэтому централизованная аналитика карточек до SKU не подтверждена.
9. **QR-поставки не завершены.** `OPSMPC-183` приостановлена; тестовая поставка не подтверждена.
