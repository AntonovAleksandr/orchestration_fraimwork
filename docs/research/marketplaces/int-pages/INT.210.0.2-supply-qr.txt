h1. Назначение и логика

Метод отдаёт QR-код поставки Wildberries — этикетку, которую наклеивают на паллету и по которой поставку принимают на складе ВБ.

*Основной способ получить QR — ответ метода отгрузки INT.210.0.3.* Он возвращает и номер поставки ВБ, и сам QR, так что в обычном сценарии печать идёт сразу по нажатию кнопки в 1С и этот метод не нужен.

Данный метод — резервный путь для одного случая: поставка отгружена, но этикетка от Wildberries на момент ответа ещё не пришла. Тогда INT.210.0.3 вернёт {{qr_ready: false}} с пояснением, и 1С опрашивает этот метод, пока этикетка не появится.

*Повторно нажимать кнопку отгрузки в этом случае нельзя* — поставка уже отгружена, и повторное нажатие ничего не исправит. Опрос этого метода — правильное действие.

Значение {{supplyID}} может быть двух видов, оба равноправны:

* *наш внутренний номер поставки* — число из поля {{internal_id}} ответа INT.210.0.3;
* *номер поставки ВБ* — строка формата {{WB-GI-<цифры>}} из поля {{supply_id}} ответа INT.210.0.3.

Форматы не пересекаются (номер ВБ всегда строка с префиксом), поэтому метод сам различает, что передано. В ответе на запрос по номеру ВБ присутствуют оба номера — {{supply_id}} (внутренний) и {{wb_supply_id}}.

h1. Параметры/тело запроса

Тела нет, параметр передаётся в пути.

|| Поле || Тип || Обяз. || Описание || Пример значения ||
| {{supplyID}} | integer или string | + | Внутренний номер поставки (поле {{internal_id}} ответа INT.210.0.3) либо номер поставки ВБ формата {{WB-GI-<цифры>}} (поле {{supply_id}} ответа INT.210.0.3) | {{57}} или {{WB-GI-123456}} |

{code:title=Пример запроса по внутреннему номеру|language=js|collapse=true}
GET /api/v1/station/supply/57/label
{code}

{code:title=Пример запроса по номеру поставки ВБ|language=js|collapse=true}
GET /api/v1/station/supply/WB-GI-123456/label
{code}

h1. Параметры ответа

|| Поле || Тип || Обяз. || Описание || Пример значения ||
| {{supply_id}} | integer | + | Внутренний номер поставки. При запросе по номеру ВБ — внутренний номер найденной поставки | {{57}} |
| {{wb_supply_id}} | string | - | Номер поставки ВБ. Присутствует только в ответе на запрос по номеру ВБ | {{WB-GI-123456}} |
| {{qr_ready}} | boolean | + | Признак готовности QR-кода. При {{false}} поля {{qr}} в ответе нет | {{true}} |
| {{qr}} | string (base64) | - | QR-код поставки. Данные бинарные, передаются в base64 — перед печатью декодировать | {{JVBERi0xLjQK...}} |

{code:title=Пример ответа — QR готов|language=js|collapse=true}
HTTP/1.1 200 OK

{
  "supply_id": 57,
  "qr_ready": true,
  "qr": "JVBERi0xLjQK..."
}
{code}

{code:title=Пример ответа на запрос по номеру ВБ|language=js|collapse=true}
HTTP/1.1 200 OK

{
  "supply_id": 57,
  "wb_supply_id": "WB-GI-123456",
  "qr_ready": true,
  "qr": "JVBERi0xLjQK..."
}
{code}

{code:title=Пример ответа — QR ещё не пришёл|language=js|collapse=true}
HTTP/1.1 200 OK

{
  "supply_id": 57,
  "qr_ready": false
}
{code}

h1. Описание и обработка ошибок

|| HTTP || Код ошибки || Текст || Действие ||
| 500 | {{label_failed}} | cannot read the supply label | Повторить запрос; при повторении — в поддержку. Тот же код вернётся для неизвестного номера поставки (и внутреннего, и ВБ) — тогда сначала проверить номер по ответу INT.210.0.3 |

Отдельно про {{qr_ready: false}}: это *не ошибка*. Поставка отгружена, состав зафиксирован, ждём только QR-код от Wildberries. Разумный порядок для 1С — опрос раз в 5–10 секунд в течение нескольких минут, дальше сообщение оператору и обращение в поддержку.

h1. Связанные интеграции

INT.210.0.1 — стикер сборочного задания.

INT.210.0.3 — передача списка заказов при отгрузке поставки, основной источник QR-кода.
