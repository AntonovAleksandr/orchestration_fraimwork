h1. Назначение и логика

Метод превращает «виртуальную» поставку в реальную: склад объявляет, что физически лежит в коробах на паллетах, и получает в ответ номер поставки Wildberries и её QR-код для печати.

До этого вызова поставка виртуальная. Она существует в Wildberries, в неё копятся сборочные задания, по ним печатаются стикеры, но что именно уложено в короба — знает только склад. *Список из этого запроса и есть истина*, к которой приводится и наша проекция, и поставка в Wildberries.

Отсюда два правила, которые легко перепутать:

* Задание, которого нет в списке, *не является недобором*. Оно физически существует и лежит на складе — просто не поехало этим рейсом. Такие задания автоматически переносятся в следующую виртуальную поставку, их номера возвращаются в поле {{moved_to_next_supply}}.
* Задание из списка нельзя ни отменить, ни перенести: оно уже в коробе на паллете, достать его нереально. Поэтому если Wildberries не пропускает такое задание, единственный честный ответ — *отказать в отгрузке целиком* (код 409), чтобы склад разобрался до отправки машины.

Поставку определяет сам список заказов — её номер в запросе не передаётся. 1С не знает наших номеров поставок, она узнаёт номер из ответа.

Повторное нажатие кнопки по уже отгруженной поставке безопасно: ответ будет тот же, включая QR, с признаком {{already_shipped: true}}. Это не ошибка, а идемпотентный повтор.

h1. Параметры/тело запроса

|| Поле || Тип || Обяз. || Описание || Пример значения ||
| {{warehouseID}} | string (в пути) | + | Код склада отгрузки | {{9148}} |
| {{orders}} | array of string | + | *Наши* номера заказов, которые физически присутствуют в коробах. Паллета собиралась по нашим этикеткам, номеров сборочных заданий ВБ склад не видит | {{\["3100000123", "3100000124"\]}} |

Ограничение на размер тела — 4 МБ. Поставка из 20 000 десятизначных номеров занимает около 300 КБ, то есть запас многократный.

{code:title=Пример запроса|language=js|collapse=true}
POST /api/v1/warehouse/9148/supply/ship
Content-Type: application/json

{
  "orders": [
    "3100000123",
    "3100000124",
    "3100000125"
  ]
}
{code}

h1. Параметры ответа

|| Поле || Тип || Обяз. || Описание || Пример значения ||
| {{supply_id}} | string | + | *Номер поставки в Wildberries.* Он же напечатан на QR, по нему поставку видно в личном кабинете | {{WB-GI-1234567}} |
| {{internal_id}} | integer | + | Наш внутренний номер поставки. Нужен только для повторного запроса этикетки через INT.210.0.2 | {{57}} |
| {{already_shipped}} | boolean | + | {{true}} — поставка была отгружена ранее, это повторный вызов | {{false}} |
| {{qr_ready}} | boolean | + | Признак готовности QR. При {{false}} печатать нечего, см. {{qr_message}} | {{true}} |
| {{qr}} | string (base64) | - | QR-код поставки. Данные бинарные, передаются в base64 — перед печатью декодировать | {{JVBERi0xLjQK...}} |
| {{qr_message}} | string | - | Пояснение, когда QR не готов. Пустая строка, когда готов | {{""}} |
| {{moved_to_next_supply}} | array of integer | - | Задания, которых не оказалось в списке. Перенесены в следующую поставку, не потеряны и не отменены | {{\[1234567891\]}} |
| {{unscanned}} | array of integer | - | Задания, объявленные присутствующими, по которым нет скана укладки на нашей станции. Отгрузку не блокирует — слово склада решающее, — но показывает, что мимо станции прошёл товар | {{\[1234567892\]}} |

{code:title=Пример ответа — отгружено|language=js|collapse=true}
HTTP/1.1 200 OK

{
  "supply_id": "WB-GI-1234567",
  "internal_id": 57,
  "already_shipped": false,
  "qr_ready": true,
  "qr": "JVBERi0xLjQK...",
  "qr_message": "",
  "moved_to_next_supply": [1234567891],
  "unscanned": []
}
{code}

{code:title=Пример ответа — отгружено, этикетка задерживается|language=js|collapse=true}
HTTP/1.1 200 OK

{
  "supply_id": "WB-GI-1234567",
  "internal_id": 57,
  "already_shipped": false,
  "qr_ready": false,
  "qr_message": "the supply is shipped; the label is not ready yet, poll the label endpoint",
  "moved_to_next_supply": [],
  "unscanned": []
}
{code}

В этом случае поставка *уже отгружена*. Повторно нажимать кнопку нельзя — нужно опрашивать INT.210.0.2 по значению {{internal_id}}.

h1. Описание и обработка ошибок

*Отказ в отгрузке — код 409.* Это осознанный ответ складу, а не сбой: по коду видно, где чинить расхождение, а в списке — какие заказы держат поставку. Номера возвращаются в нашей нумерации, чтобы их можно было показать оператору.

|| HTTP || error || Что произошло || Действие склада ||
| 409 | {{no_orders}} | Список пустой. Отгружать нечего — Wildberries отвечает на пустую поставку ошибкой | Проверить, что в 1С сформировался состав |
| 409 | {{unknown_orders}} | В списке номера, которых у нас нет вообще | Сверить номера из поля {{orders}} ответа; вероятно расхождение в 1С |
| 409 | {{split_across_supplies}} | Объявленные задания лежат в разных поставках. Состав поставки задан правилами группировки Wildberries, молча собрать их в одну нельзя | Разделить отгрузку: вызвать метод отдельно по каждой группе |
| 409 | {{supply_not_shippable}} | Поставка в состоянии, из которого не отгружают | Обращение в поддержку |
| 409 | {{marking_blocked}} | Маркировочный шлюз Wildberries не пропускает задание из списка, а перенести его нельзя — оно в коробе | Изъять указанные задания из короба либо ждать подтверждения кода маркировки. До этого отгрузка не пройдёт |

Формат ответа при отказе:

{code:title=Пример отказа|language=js|collapse=true}
HTTP/1.1 409 Conflict

{
  "error": "marking_blocked",
  "message": "",
  "orders": ["3100000124"],
  "wb_orders": [1234567891]
}
{code}

*Технические ошибки*

|| HTTP || Код ошибки || Текст || Действие ||
| 400 | {{invalid_json}} | cannot decode the shipment request | Проверить тело запроса |
| 500 | {{shipment_failed}} | cannot ship the supply | Повторить запрос. Метод идемпотентен: если поставка успела отгрузиться, повтор вернёт тот же результат с {{already_shipped: true}} |

h1. Связанные интеграции

INT.210.0.1 — стикер сборочного задания.

INT.210.0.2 — получение QR-кода поставки, резервный путь, когда этикетка задержалась.
