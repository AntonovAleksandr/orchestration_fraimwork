h1. Назначение и логика

Метод превращает «виртуальную» поставку в реальную: склад объявляет, что физически лежит в коробах на паллетах, и получает в ответ номер поставки Wildberries и её QR-код для печати.

До этого вызова поставка виртуальная. Она существует в Wildberries, в неё копятся сборочные задания, по ним печатаются стикеры, но что именно уложено в короба — знает только склад. *Список из этого запроса и есть истина*, к которой приводится и наша проекция, и поставка в Wildberries.

Отсюда два правила, которые легко перепутать:

* Задание, которого нет в списке, *не является недобором*. Оно физически существует и лежит на складе — просто не поехало этим рейсом. Такие задания автоматически переносятся в следующую виртуальную поставку, их номера возвращаются в поле {{moved_to_next_supply}}.
* Задание из списка может оказаться чужим: числиться в другой поставке, другом направлении или вовсе не существовать в системе. С 2026-08-26 такое задание *не останавливает отгрузку*: вынимать коробку из тысяч на паллете нереально. Если его поставка того же направления ещё открыта, задание автоматически переносится в отгружаемую; иначе остаётся в своей поставке. Каждый такой случай возвращается в поле {{foreign_supply_orders}} и фиксируется в реестре отклонений для разбора.
* Отказ целиком (код 409) остаётся только там, где отгрузка невозможна технически: пустой список, нет поставки этого склада для указанных заказов, неподтверждённые коды маркировки, незавершённая синхронизация или предыдущая отгрузка.

Поставку определяет сам список заказов — её номер в запросе не передаётся. 1С не знает наших номеров поставок, она узнаёт номер из ответа. Если заказы списка числятся в нескольких поставках, отгружается поставка с большинством заказов; остальные — в {{foreign_supply_orders}}.

Повторное нажатие кнопки по уже отгруженной поставке безопасно: ответ будет тот же, включая QR, с признаком {{already_shipped: true}}. Это не ошибка, а идемпотентный повтор.

h1. Параметры/тело запроса

|| Поле || Тип || Обяз. || Описание || Пример значения ||
| {{warehouseID}} | string (в пути) | + | Код склада отгрузки | {{9148}} |
| {{orders}} | array of string | + | *Наши* номера заказов, которые физически присутствуют в коробах. Паллета собиралась по нашим этикеткам, номеров сборочных заданий ВБ склад не видит | {{\["3100000123", "3100000124"\]}} |

Ограничение на размер тела — 4 МБ. Поставка из 20 000 десятизначных номеров занимает около 300 КБ, то есть запас многократный.

{code:title=Пример запроса|language=js|collapse=true}
POST /api/v1/warehouse/9148/supply/ship
Content-Type: application/json

{
  "orders": [
    "3100000123",
    "3100000124",
    "3100000125"
  ]
}
{code}

В этом случае поставка *уже отгружена*. Повторно нажимать кнопку нельзя — нужно опрашивать INT.210.0.2 по значению {{internal_id}}.

h1. Описание и обработка ошибок

*Отказ в отгрузке — код 409.* Это осознанный ответ складу, а не сбой: код показывает класс проблемы, {{message}} — точную причину и действие, {{orders}} — заказы, которые держат поставку, в нашей нумерации. Заказы из чужих поставок и неизвестные номера отказом не являются — они приходят в поле {{foreign_supply_orders}} успешного ответа.

|| HTTP || error || message || Действие склада ||
| 409 | {{no_orders}} | Список заказов пуст: отгружать нечего. Проверьте состав отгрузки в 1С. | Проверить, что в 1С сформировался состав |
| 409 | {{no_orders}} | Ни один из указанных заказов не найден в системе: отгружать нечего. Сверьте номера заказов в 1С. | Сверить номера из поля {{orders}} ответа с 1С |
| 409 | {{no_orders}} | Wildberries отклонил все заказы поставки: отгружать нечего. Поставка расформирована без QR; заказы остаются на складе до следующей поставки. | Обращение в поддержку |
| 409 | {{supply_not_shippable}} | Ни один из указанных заказов не входит ни в одну поставку: отгружать нечего. Обратитесь в поддержку. | Обращение в поддержку |
| 409 | {{supply_not_shippable}} | Ни один из указанных заказов не принадлежит поставке склада \{warehouseID\}, доступной для отгрузки. Обратитесь в поддержку. | Проверить склад отгрузки; при расхождении — обращение в поддержку |
| 409 | {{composition_pending}} | Состав поставки ещё передаётся в Wildberries. Повторите запрос через минуту; действий со стороны склада не требуется. | Повторить запрос через минуту |
| 409 | {{predecessor_pending}} | Предыдущая поставка ещё завершает отгрузку. Повторите запрос после её завершения; укладка в текущую поставку продолжается. | Повторить запрос после завершения предыдущей отгрузки |
| 409 | {{shipment_declaration_mismatch}} | Для этой поставки уже зафиксирован другой состав отгрузки. Повторите запрос с исходным списком заказов. | Повторить запрос с исходным списком; при расхождении — обращение в поддержку |
| 409 | {{marking_blocked}} | Wildberries не подтвердил коды маркировки заказов из поля orders. Отгрузка невозможна до подтверждения кодов. | Дождаться подтверждения кодов маркировки и повторить запрос |

Формат ответа при отказе:

{code:title=Пример отказа|language=js|collapse=true}
HTTP/1.1 409 Conflict

{
  "error": "marking_blocked",
  "message": "Wildberries не подтвердил коды маркировки заказов из поля orders. Отгрузка невозможна до подтверждения кодов.",
  "orders": ["3100000124"],
  "wb_orders": [1234567891]
}
{code}

*Технические ошибки*

|| HTTP || Код ошибки || Текст || Действие ||
| 400 | {{invalid_json}} | cannot decode the shipment request | Проверить тело запроса |
| 500 | {{shipment_failed}} | cannot ship the supply | Повторить запрос. Метод идемпотентен: если поставка успела отгрузиться, повтор вернёт тот же результат с {{already_shipped: true}} |

h1. Связанные интеграции

INT.210.0.1 — стикер сборочного задания.

INT.210.0.2 — получение QR-кода поставки, резервный путь, когда этикетка задержалась.
