## Уточняющий вопрос по полю `acceptedByRegistry`

При запросе вашего метода выбора отправителя (по «Глория Джинс» + «Подольск») наш адрес — и **все** записи «Глория Джинс / Подольск» — возвращаются со статусом **`acceptedByRegistry: false`**. Просим пояснить:
- что означает это поле и влияет ли оно на регистрацию заказа методом `createOrder`;
- должен ли адрес отправителя (code 6003 → id 67123424593) быть `acceptedByRegistry: true`, и если да — как его принять в реестр (нужна ли переотправка адреса с нашей стороны методом `ns:updateAddress`).

Само по себе значение `false` у всех записей может быть штатным — поэтому это вопрос, а не утверждение о причине. Первичная же просьба — переактуализировать адрес отправителя по коду 6003 в адресном модуле ARGIS (см. ниже).

## Связь с ранее решённым обращением

На прошлой неделе у нас была схожая по классу проблема в методе **расчёта** доставки: ваш справочник не разбирал наименование населённого пункта из-за аббревиатур/лишних символов. По вашей рекомендации (передавать название без аббревиатур) мы скорректировали данные на своей стороне; исправление подтверждено 11.06 09:32 МСК.

Сейчас аналогичная по характеру ошибка разбора адреса возникает в методе **createOrder**, но по **адресу отправителя**, и затрагивает тот же модуль `ARGIS.ARG_REQ_ADDR`.

Не исключаем, что после обновления вашего адресного справочника 10–11 июня перестала разбираться сама запись адреса склада-отправителя — `142184, г Подольск, д Гривно, территория промышленного парка Гривно, дом 1` (вложенные «г Подольск» + «д Гривно», нестандартный «промпарк» вместо улицы). По коду 6003 этот адрес успешно регистрировал заказы до 11.06 11:31 МСК, то есть формат не менялся — изменилось его распознавание на вашей стороне. Один из возвращаемых вариантов ошибки это подтверждает: `ORA-20201: Ошибка разбора адреса… задана пониженная точность, не заданы обязательные атрибуты "Почтовый индекс или Населённый пункт"`.

Просьба: подсказать корректную форму записи адреса склада для вашего обновлённого справочника (или нормализовать её на вашей стороне), чтобы код 6003 снова резолвился. При необходимости мы переотправим адрес методом `ns:updateAddress`.
