# Режим киоска — канонические требования (KR-NN)

Источник: **бриф владельца (Александр) от 2026-06-28**. Других утверждённых источников (Confluence/Jira) на старте нет.
Это рабочая формулировка для скоупинга — **подлежит утверждению** (см. колонку «Статус согласования»).

**Легенда фазы:** `MVP` — пилот на 2–3 магазинах · `P2` — расширение (после MVP) · `NFR` — нефункциональное/сквозное.
**Статус согласования:** 🟡 со слов владельца, требует утверждения · ⚪ открытый вопрос (нужно решение).

---

## MVP (пилот)

| KR | Требование | Фаза | Согл. |
|---|---|---|---|
| **KR-1** | **Инстанс киоска.** Запустить режим киоска как **отдельный инстанс** `site-kiosk` (по образцу ASM/аватар) со своим доменом и слегка модифицированным фронтом. Альтернатива для скорости — feature-flag/конфиг-режим на текущем фронте. Решение — на Stage 01. | MVP | ⚪ |
| **KR-2** | **Старт сразу в каталоге.** Стартовая точка приложения — каталог в **корневой категории (root, «все товары»)**, без показа главной страницы. | MVP | 🟡 |
| **KR-3** | **Текущий интерфейс (планшетный).** Переиспользовать текущую вёрстку (как для планшета); значимой переверстки не делать. Допустимы точечные kiosk-правки (скрыть лишнее). | MVP | 🟡 |
| **KR-4** | **Фильтр «товары только этого магазина».** Кнопка/режим, показывающий товары привязанного магазина. На базе **существующего** фильтра по магазинам в листинге. Нужен механизм **привязки киоска к магазину** (на пилоте — простой: конфиг/URL/домен). | MVP | 🟡 |
| **KR-5** | **Авто-разлогин после заказа.** После успешного создания заказа клиент автоматически разлогинивается (сессия сбрасывается). | MVP | 🟡 |
| **KR-6** | **Авто-разлогин по бездействию.** При отсутствии взаимодействия N секунд — попап с обратным отсчётом («разлогиним через 1 мин»); по истечении — сброс сессии и возврат в исходное состояние (каталог root, разлогинен). Значение N (30–60 сек) — **согласовать**. | MVP | ⚪ |
| **KR-7** | **Развёртывание на железе.** Пилотное железо с Ubuntu в **режиме киоска** (полноэкранный браузер, chromium `--kiosk`), автозапуск на нужном URL, защита от выхода. Пилот — 2–3 магазина. | MVP | 🟡 |

## Phase 2 (после MVP)

| KR | Требование | Фаза | Согл. |
|---|---|---|---|
| **KR-8** | **Гостевой чекаут.** Возможность оформить заказ **без логина** — указав ФИО + телефон + адрес (как обычно). Влияет на customer-auth/customers/checkout/Integration/OMS. | P2 | ⚪ |
| **KR-9** | **Возможный Android-инстанс.** Если Ubuntu/браузер-киоск не подойдёт — устройство на Android + спец-приложение (дольше; оценить отдельно). | P2 | ⚪ |

## Нефункциональные / сквозные (NFR)

| KR | Требование | Фаза | Согл. |
|---|---|---|---|
| **KR-10** | **Безопасность общего девайса.** При сбросе сессии (KR-5/KR-6) гарантированно очищать персональные данные (токены, корзина, профиль, форма чекаута), не оставлять чужой контекст следующему покупателю. | MVP | ⚪ |
| **KR-11** | **Аналитика трафика киоска.** Уметь отделять/маркировать трафик киоска (источник = kiosk + магазин) для отчётности. Объём — уточнить (может быть P2). | P2 | ⚪ |
| **KR-12** | **Минимум модификаций / скорость.** Базовый приоритет: на 1-й фазе минимизировать изменения и время до запуска; сложные ветки (гостевой чекаут, Android, богатая привязка магазина) — на потом. | MVP | 🟡 |

## Вопросы на согласование (входят в Stage 07 / к владельцу и бизнесу)

1. **Инстанс vs флаг (KR-1):** заводим отдельный `site-kiosk` сразу или стартуем флагом на текущем фронте для скорости пилота? (влияет на срок и на деплой/домен)
2. **Таймаут бездействия (KR-6):** 30 или 60 сек до попапа? сколько на обратный отсчёт? поведение по таймеру (logout + reset до каталога root).
3. **Привязка магазина (KR-4):** через домен/субдомен на магазин, query-param, конфиг устройства или выбор магазина на экране? на пилоте — что проще.
4. **Логин на киоске (MVP):** как покупатель логинится на общем экране — телефон+СМС-код? Это база для KR-5/KR-6. (Гостевой чекаут KR-8 — только P2.)
5. **Каталог root для киоска:** показывать ассортимент всего магазина или весь сайтовый? связано с KR-4 (по умолчанию — товары магазина или все?).
6. **Юр./фискальные нюансы заказа из киоска** (если оформляется как онлайн-заказ с доставкой/самовывозом) — нужен ли отдельный канал продаж/признак. (для Stage 06/07)
