# Beauty / COSMETICS — подготовка production-релиза

**Владелец:** Александр  
**Jira:** `OPSOMN002-15`  
**Старт журнала:** 2026-07-17  
**Статус:** живой релизный проект; обновляется после каждого действия с кодом, данными или окружением.

Цель проекта — последовательно вывести группу `COSMETICS=5` и связанные Beauty-категории, Product Types и
`types[].groups` от PIM до mobile-фильтров, не смешивая кодовые изменения с мастер-данными и навигацией CMS.

## Правила ведения

- Факт, план и открытый вопрос не смешиваются в одной формулировке.
- После изменения репозитория в `ACTION-LEDGER.md` записываются ветка, SHA до/после, файлы, генерация и проверки.
- После действия с окружением записываются target/environment, команда или операция, результат и необходимость повтора.
- Любая мастер-операция содержит владельца, входной источник, read-only проверку и критерий отката/исправления.
- Production-операции не выполняются только на основании этой спеки: каждый gate должен быть отмечен как пройденный.
- CMS L1 «Косметика» для навигации является отдельным потоком и не заменяет `PIM categories.group=5`.

## Каноническая цепочка MD-006

```text
product
  → category_product_links
  → category(group = COSMETICS)
  → product_type_category_links
  → Product Type
  → catalog-cache / ES types[].groups
  → POST /mobile/v4/catalog/filters
```

`target_category_id` не является источником `types[].groups` и не заполняется `ImportProductAction`.
