# Оркестрация задач: универсальное ядро

Процесс выполнения задач с помощью команды агентов: вводная и самопроверка, работники по фазам,
ревью с проверкой строк, гейт сдачи, приёмка, состояние задачи и журнал событий. Ядро не знает
проекта, в котором работает: проектные значения задаются переменными окружения.

## Состав

- `framework/` — ядро на Python: состояние задачи, требования, вопросы, релизы, публикация замечаний ревью.
  Адаптер GitLab в `framework/adapters/`. Граница ядра проверяется `framework/tests/test_boundary.py`.
- `scripts/orch/` — команды и хуки: `orchestrate.sh` (главный вход), гейт, подтверждение внешних записей,
  хуки Claude Code (`hooks/`).
- `.claude/skills/` — процессные скиллы (вводная, выполнение, делегирование, ревью, сдача) и экспертные
  (ревью, исследование, Go, codegraph, фреймворк).
- `.claude/agents/` — универсальные агенты: архитектор, ревьюер, приёмка, Go, Camunda.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ORCH_TASKS_DIR` | `.tasks` | каталог состояния задач |
| `ORCH_RESEARCH_MODEL` | `claude-haiku-5-5` | модель разведки |
| `ORCH_RESERVE_MB` | `2048` | порог свободной памяти для запуска работника |
| `ORCH_MAX_SWAP_MB` | `4096` | порог свопа для запуска работника |
| `ORCH_WORKER_MB` | `700` | оценка памяти работника для статуса |
| `ORCH_FORCE` | — | обход заслона ресурсов (`1`) |
| `ORCH_TASK_KEY_RE` | — | шаблон ключа задачи для хуков |
| `ORCH_REPO_GLOBS` | — | маски вложенных клонов; пусто — проверка дерева отключена |
| `ORCH_TRACKER_URL` | — | адрес трекера задач для ссылок в отчётах |
| `ORCH_PROJECT_TOKENS` | — | проектные токены для проверки границы ядра |

## Проверка

```bash
bash tests/run_all.sh
```

## Внешние записи

Записи во внешние системы (MR, комментарии, трекер) требуют подтверждения пользователя
(`scripts/orch/approve.sh`). Слияние в стейдж и прод агент сам не выполняет.
